### Precise justification for A-02

For `n≥1`, couple the planted challenge to an honest Lamport execution: all public-key entries have their honest joint distribution, and the uniformly selected pair `(i,c)` is independent of the honest execution. The real reduction agrees with this execution whenever it does not need to reveal the planted preimage.

For an accepting forgery following query `m`, with fresh output message `m′`, the fraction of favorable planted pairs is

\[
\frac{\#\{(i,c):m_i\ne c=m'_i\}}{2n}
=\frac{\#\{i:m_i\ne m'_i\}}{2n}
\ge \frac1{2n}.
\]

On these pairs the reduction answers the query and extracts a preimage of the challenge. If there was no query, exactly one bit `c=m′_i` works for every position, so the fraction is `n/(2n)=1/2`. Summing over successful honest executions gives the stated `ε(n)/(2n)` lower bound. This avoids asserting independence after conditioning on non-abort. At the machine level, exact uniform sampling from `[n]` need not be assumed: a non-uniform reduction can use a best position as `O(log n)` bits of advice and a fair bit `c`, retaining this bound. A truncated uniform-position sampler is another option with an explicitly accounted loss.

This is a mathematical correction to the sketch; the admitted security theorem has not thereby been filled in Lean.

## Answers to the five issued questions

| Question | Assessment |
|---|---|
| Search games, freshness, budget, output lengths | **Correct.** Each `forgeGame` requires `∀ e ∈ res.2.2, e.2.1 ≠ output_message`, so a query anywhere in the executed log defeats freshness. `withLog` appends every answered query. `OneTimeSecure` sets the budget to **1**, permitting **at most one** actual signing query and also zero queries. `buildComp` still permits a final return at remaining budget 0, but answers no second query. The bit codec requires a canonical final payload of exactly message length plus tag/signature length, then `splitBits` separates those fields. Signature forgers receive `pk`; MAC forgers do not receive the secret key. |
| Repaired CRH and its threshold | **Faithful with the declared finite-parameter adaptation.** `CRH` is syntax; `Compresses` and `CollisionResistant` are separate properties. Compression includes both mapping into the declared range and strict cardinality decrease, eventually for every generated index. Both collision inputs must pass `inDom`. An empty/singleton domain can make collision resistance vacuous, but cannot satisfy eventual compression together with the mapping clause. A finite threshold changes finite-parameter behavior, not asymptotic security. |
| Discrete-log hypothesis and one-bit compression | **Correct conditional theorem.** `hV` forces valid full-group indices and `m=p−1`; `G.DLHard` uses ideal uniform exponents and demands negligible success for every non-uniform machine. From the generator threshold onward, `p<2^n`, and the repaired domain and range have sizes `2(p−1)` and `p−1`. Both cardinality-ratio compression and the declared encoding-width decrease `(n+1)→n` are real. The assumption is generator-relative full-group hardness, not an inference from PS10's prime-order Assumption 52.2; the module discloses that distinction. |
| Hash-and-sign domain repair and existence conclusion | **Correct sufficient repair, not minimal quantification.** If the queried and forged hashes coincide, the full-domain hypothesis makes both messages eligible for the collision game; otherwise the same output is a fresh base-scheme forgery. A zero-query forgery belongs to the latter case. The existential theorem correctly instantiates Lamport with hash output length `n`, but establishes only the disclosed fixed-length version of the source conclusion. Compression is unnecessary for this security reduction, so its absence among these theorem hypotheses is benign. |
| Lamport key layout and verifier length guard | **Correct.** Each secret segment contains two `n`-bit preimages. If each image has length `L(n)`, the inner pair has length `3L(n)+2`; one tuple block has length `2(3L(n)+2)+2=6L(n)+6`. The verifier consumes exactly these tuple blocks. It rejects a raw message of length other than `n` or a raw signature of length other than `n²`; thus accepted signature blocks supplied to `E` have the length where `hfE` applies. |

The source's exponent-domain error is genuinely repaired: for `p=5`, `g=2`, the unrestricted 3-bit exponents 0 and 4 yield the same hash with selector 0. The formal domain rejects 4. For valid exponents, a collision with equal selectors would force equal exponents modulo `m`, hence equal inputs; different selectors yield the discrete logarithm by the signed difference modulo `m`.

## In-scope correctness proofs and security sketches

### PRF MAC correctness

The coin-key machine returns an `n`-bit key. Evaluator agreement gives `E(⟨k,m⟩)=F_n(k,m)` as an exactly `n`-bit list. Padding at width `n` changes nothing, and the verifier compares that same list with itself. The proof uses this identity for arbitrary generator and tag coin tapes, including the unique empty tape at `n=0`; it does not use PRF security.

For the admitted security statement, the sketch's oracle distinguisher can make one final query beyond the forger's budget. On a genuinely fresh message the random-function value is independent and uniform, giving success at most `2^{-n}`. Polynomial budget `q+1` is available, and the sketch names the appropriate interactive/machine bridges rather than assuming a closure theorem for an arbitrary higher-order callback.

### Lamport correctness and length lemmas

The inspected source establishes the following identities, for every honest tape and message:

\[
|\rho|=2n^2,\qquad |x_i^b|=n,\qquad |E(\langle1^n,x_i^b\rangle)|=L(n),
\]
\[
|\langle E(x_i^0),E(x_i^1)\rangle|=3L(n)+2,
\qquad
|\langle\langle E(x_i^0),E(x_i^1)\rangle,[]\rangle|=6L(n)+6,
\]
\[
\sigma=x_1^{m_1}\Vert\cdots\Vert x_n^{m_n},\qquad |\sigma|=n^2.
\]

Here the second line suppresses `E`'s already fixed parameter input. `coinBlock_flatten_ofFn` recovers each selected signature block and each encoded public-key block. The two verifier block loops therefore emit the identical image at every position. The length guard succeeds, padding does not alter the honest signature, and tuple equality holds. The zero-length cases of the flattening and slicing lemmas are consistent; there is no hidden division by `n` in correctness.

I inspected the proofs of the helper length/slicing statements, both run equations, `length_lamportEval`, and `lamportVerFun_sign`; their induction, length and component arguments support these identities. The key block's extra tuple wrapper is included in the `6L+6` calculation. The security reduction extracts **a** preimage, so collisions in a non-injective one-way function do not invalidate the intended theorem.

### Hash-and-sign correctness

The generator tape splits into the original signature-generator tape and the independent hash-generator tape. Both new key components contain the same sampled index. `runAt_hsSign` identifies the transformed signer, with the same signing coins, with the original signer on the hash word. The equality `hlen` identifies that word's width with the base message width. The original `S.correct` then verifies the same keys, message and padded signature. No collision-resistance, compression or full-domain hypothesis is needed for this honest-correctness identity; the latter domain hypothesis is used by the security reduction instead.

The supplied axiom census lists 278 authentication identities. The only five listed with `sorryAx` are `prfMAC_secure`, `lamport_oneTimeSecure`, `dlHash_crh`, `hashAndSign_oneTimeSecure` and the derived `exists_oneTimeSecure_of_crh_owf`. It reports standard axioms only for `prfMAC`, `lamport`, `lamportVerFun_sign` and `hashAndSign`. This corroborates the source-level distinction between proved construction correctness and admitted substantive security; it is not a fresh kernel run by this auditor.

## Adversarial instances and independent finite checks

| Instance | Result |
|---|---|
| Query an earlier message, then a different last message, then replay the earlier message | The freshness conjunction fails on the earlier entry even though the last query differs. This tests complete-log freshness, not just last-query checking. |
| Attempt a second signing query at budget 1 | Exactly one query is answered/logged; the second request produces the declared default final vector. A legitimate return after the first answer is still allowed. |
| Zero queries and budget 0 | A final return is permitted. An attempted query receives no answer. Thus zero-query forgery attacks are included rather than discarded. |
| Malformed/wrong-width forger outputs | The forge codec uses its all-false fallback; the collision game uses its explicitly declared padding/truncation convention. Neither grants power beyond an adversary explicitly outputting the resulting fixed-width strings. These fallbacks are not asserted to reject every insecure scheme. |
| `n=0` for PRF MAC / Lamport | Correctness still holds. A public zero-query forgery can succeed at this parameter; negligible bounds may absorb finitely many such parameters. A one-time oracle query on the sole empty message destroys freshness. |
| Empty or singleton CRH domain | Collision resistance alone can be vacuous. Eventual compression plus range containment excludes these cases: a nonempty domain needs a nonempty range, and strict cardinality decrease then needs at least two domain elements. |
| Unrestricted exponent domain at `p=5, g=2` | `(0,0)` and `(4,0)` collide; formal `inDom` rejects exponent 4 because `m=4`. The repair blocks the exact attack that would invalidate the source's unrestricted reading. |
| Short/malformed Lamport signature with a hostile off-length evaluator | The raw verifier's length guard rejects it; valid-length signature blocks stay inside `hfE`'s agreement domain. |
| Remove `hdom` from hash-and-sign | Starting from any full-domain secure compressing family, restrict a new family's domain to inputs with leading bit 0, reuse the original family there, and make its evaluator constant on leading-bit-1 inputs. Its in-domain collision security is preserved, but querying one excluded message lets the forger reuse its signature on a distinct excluded message. This shows the omitted hypothesis cannot simply be dropped. |
| Use a fixed small discrete-log group at every growing parameter | Even if padded indices remain well formed, guessing exponent 0 succeeds with constant probability `1/m`; such a generator cannot meet `G.DLHard`. The generator-relative hypothesis is not made automatically true by padding small primes. |
