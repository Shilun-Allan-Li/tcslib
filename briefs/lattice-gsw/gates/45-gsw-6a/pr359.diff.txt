+# Bounded-width branching programs
+
+Branching programs of bounded width in the general model of [Bar89, §1] (instructions produce
+maps `[w] → [w]`; permutation programs are a predicate), the host `BranchingProgram.evalWith`
+that runs a program on state vectors (registry row H18), and both directions of Barrington's
+results, namely formulas of depth `d` to width-5 permutation programs of length `≤ 4^d`, programs
+of length `l` to formulas of depth `O(log l)`, and BWBP = nonuniform NC¹ = PBP₅.

+/-!
+# Barrington's Theorem 1: formulas to width-5 permutation programs
+
+[Bar89, Thm 1]: a fan-in-2 AND/OR formula of depth `d` over literals is *five-cycle recognized*
+by a width-5 permutation branching program of length at most `4^d`.  The construction
+`BranchingProgram.barrington` is computable (P6-Q13): Lemma 1's conjugator is the explicit
+`θ (σ^k 0) = τ^k 0`, and the OR case goes through Lemma 2 by De Morgan.
+
+## Main definitions
+
+* `BranchingProgram.IsFiveCycle`, `BranchingProgram.FiveCycleRecognizes` — five-cycles and
+  five-cycle recognition [Bar89, §3].
+* `BranchingProgram.sigma1`, `sigma2` — Lemma 3's five-cycles `(12345)`, `(13542)`, 0-based.
+* `BranchingProgram.conjugator` — Lemma 1's explicit conjugator (with `conjugatorIndex`,
+  `conjugatorFun`, `conjugatorTable`).
+* `BranchingProgram.commutatorProgram` — the AND step `B₁ B₂ B₁' B₂'` of Thm 1's proof.
+* `BranchingProgram.barrington` — Barrington's program for a formula and an output.
+
+## Main results
+
+All are statements of the 6a statement phase (targets admitted with `sorry`), except the readers.
+
+* `isFiveCycle_sigma1`, `isFiveCycle_sigma2`, `isFiveCycle_commutator` — Lemma 3 (C9).
+* `conjugator_conj` — the conjugator conjugates (C10).
+* `FiveCycleRecognizes.conj`, `FiveCycleRecognizes.complementLast` — Lemmas 1 and 2 (C11, C12).
+* `barrington_recognizes`, `barrington_length_le`, `barrington_length_pos`,
+  `isPermutation_barrington`, `barrington_yield_zero` — Thm 1 (C13–C16).
+
+## Conventions and deviations
+
+* **Orders.** Instructions follow BV14's order (`map0` on `0`) and programs compose in program
+  order (`Defs.lean`).  Bar89's commutator `σ₁σ₂σ₁⁻¹σ₂⁻¹`, read left to right, is the Mathlib
+  product `sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1`, which is `(13254)` 0-based, i.e. the cycle
+  `0 ↦ 2 ↦ 1 ↦ 4 ↦ 3 ↦ 0`; the right-to-left reading gives `(14352)` instead (r3 §H3.6).
+* **Cycle notation.** `sigma1`, `sigma2` are written `List.formPerm [0, 1, 2, 3, 4]` and
+  `List.formPerm [0, 2, 4, 3, 1]`: Mathlib's `c[…]` notation lives in
+  `Mathlib.GroupTheory.Perm.Cycle.Concrete`, which is not in the pinned Mathlib cache;
+  `c[l]` is `Cycle.formPerm (Cycle.ofList l)`, which is `List.formPerm l` (`Cycle.formPerm_coe`).
+* **Constants and literals.** [Bar89, Thm 1] allows "inputs and negated inputs"; `TreeCircuit`
+  also has constant nodes `node true []`, `node false []` and fan-in-1 nodes, which get their own
+  trivial cases (the ingest's transcription note).  A constant reads variable `0`, hence
+  `[NeZero n]`.
+* **OR gates.** "Appeal to Lemma 2" is De Morgan through `complementLast` (see `barrington`).
+* **Fan-in.** `barrington` is total; at a node of fan-in above 2 it uses the first two children
+  only.  The theorems assume `c.maxFanin ≤ 2`, where nothing is dropped.
+* **Reading.** BV14 reads the state reached from the start state; here the start state is `0`
+  and the accepting reading is `σ 0` (C16).
+
+## References
+

+* [BV14] Z. Brakerski, V. Vaikuntanathan, *Lattice-based FHE as secure as PKE*, ITCS 2014,
+  pp. 1–12; IACR ePrint 2013/541.
+-/

+/-! ### Five-cycles and five-cycle recognition -/
+
+/-- `σ` is a five-cycle: its cycle type is `{5}`, `σ.cycleType = {5}` (decidable)
+[Bar89, §3, p003-b001]. -/
+def IsFiveCycle (σ : Perm (Fin 5)) : Prop :=
+  σ.cycleType = {5}
+
+/-- Reader of `IsFiveCycle`: `IsFiveCycle σ ↔ σ.cycleType = {5}`. -/
+theorem isFiveCycle_iff (σ : Perm (Fin 5)) : IsFiveCycle σ ↔ σ.cycleType = {5} := Iff.rfl
+
+instance instDecidablePredIsFiveCycle : DecidablePred IsFiveCycle := fun σ =>
+  inferInstanceAs (Decidable (σ.cycleType = {5}))
+
+/-- `B` five-cycle recognizes `A` with output `σ`: `σ` is a five-cycle, and `B.yield x` is `σ` on
+`A` and the identity off `A`,
+`IsFiveCycle σ ∧ ∀ x, (A x → B.yield x = σ) ∧ (¬ A x → B.yield x = id)`
+[Bar89, §3, p003-b001]. -/
+def FiveCycleRecognizes (B : BranchingProgram 5 n) (A : (Fin n → Bool) → Prop)
+    (σ : Perm (Fin 5)) : Prop :=
+  IsFiveCycle σ ∧ ∀ x, (A x → B.yield x = σ) ∧ (¬ A x → B.yield x = id)
+
+/-- Reader of `FiveCycleRecognizes`: `FiveCycleRecognizes B A σ ↔
+IsFiveCycle σ ∧ ∀ x, (A x → B.yield x = σ) ∧ (¬ A x → B.yield x = id)`. -/
+theorem fiveCycleRecognizes_iff (B : BranchingProgram 5 n) (A : (Fin n → Bool) → Prop)
+    (σ : Perm (Fin 5)) :
+    FiveCycleRecognizes B A σ ↔
+      IsFiveCycle σ ∧ ∀ x, (A x → B.yield x = σ) ∧ (¬ A x → B.yield x = id) :=
+  Iff.rfl

+/-! ### Lemma 1's explicit conjugator -/
+
+/-- The position of `i` on the orbit of `0` under `σ`: the first `k < 5` with `(σ ^ k) 0 = i`, or
+`0` if there is none,
+`conjugatorIndex σ i = ((List.range 5).find? fun k => (σ ^ k) 0 = i).getD 0`.  Glue for
+[Bar89, Lemma 1 proof, p003-b003]; for a five-cycle every `i` is found. -/
+def conjugatorIndex (σ : Perm (Fin 5)) (i : Fin 5) : ℕ :=
+  ((List.range 5).find? fun k => (σ ^ k) 0 = i).getD 0
+
+/-- Reader of `conjugatorIndex`:
+`conjugatorIndex σ i = ((List.range 5).find? fun k => (σ ^ k) 0 = i).getD 0`. -/
+theorem conjugatorIndex_eq (σ : Perm (Fin 5)) (i : Fin 5) :
+    conjugatorIndex σ i = ((List.range 5).find? fun k => (σ ^ k) 0 = i).getD 0 := rfl
+
+/-- The conjugating map `σ^k 0 ↦ τ^k 0`: `conjugatorFun σ τ i = (τ ^ conjugatorIndex σ i) 0`
+[Bar89, Lemma 1 proof, p003-b003]. -/
+def conjugatorFun (σ τ : Perm (Fin 5)) (i : Fin 5) : Fin 5 :=
+  (τ ^ conjugatorIndex σ i) 0
+
+/-- Reader of `conjugatorFun`: `conjugatorFun σ τ i = (τ ^ conjugatorIndex σ i) 0`. -/
+theorem conjugatorFun_eq (σ τ : Perm (Fin 5)) (i : Fin 5) :
+    conjugatorFun σ τ i = (τ ^ conjugatorIndex σ i) 0 := rfl
+
+/-- The values of `conjugatorFun σ τ` stored as a list:
+`conjugatorTable σ τ = List.ofFn (conjugatorFun σ τ) = [f 0, f 1, f 2, f 3, f 4]` with
+`f = conjugatorFun σ τ`.  `conjugator` reads its map from this list (`getD_conjugatorTable`), so
+that evaluating a conjugator computes the five values once and later applications are lookups;
+without it, Barrington's nested conjugates cost time exponential in the depth when evaluated.
+Glue for [Bar89, Lemma 1 proof, p003-b003]. -/
+def conjugatorTable (σ τ : Perm (Fin 5)) : List (Fin 5) :=
+  List.ofFn (conjugatorFun σ τ)
+
+/-- Reader of `conjugatorTable`: `conjugatorTable σ τ = List.ofFn (conjugatorFun σ τ)`. -/
+theorem conjugatorTable_eq (σ τ : Perm (Fin 5)) :
+    conjugatorTable σ τ = List.ofFn (conjugatorFun σ τ) := rfl
+
+/-- Looking up the table gives the map: `(conjugatorTable σ τ).getD i 0 = conjugatorFun σ τ i`. -/
+theorem getD_conjugatorTable (σ τ : Perm (Fin 5)) (i : Fin 5) :
+    (conjugatorTable σ τ).getD i 0 = conjugatorFun σ τ i := by
+  rw [conjugatorTable_eq, List.getD_eq_getElem?_getD, List.getElem?_ofFn]
+  simp
+
+/-- The explicit conjugator of two five-cycles: the permutation `θ` with `θ (σ^k 0) = τ^k 0`
+for `k < 5`, i.e. `conjugatorFun σ τ` (read from the list `conjugatorTable σ τ`) packaged with
+its computable inverse (`Fintype.bijInv`) when it is a bijection, and the identity otherwise
+[Bar89, Lemma 1 proof, p003-b003: "there exists some permutation `θ` with `τ = θσθ⁻¹`"].
+Computable (P6-Q13); it is not `Equiv.ofBijective`, whose inverse is noncomputable.  For
+five-cycles `σ`, `τ` the map is a bijection and `θ * σ * θ⁻¹ = τ` (C10). -/
+def conjugator (σ τ : Perm (Fin 5)) : Perm (Fin 5) :=
+  let t := conjugatorTable σ τ
+  if h : Function.Bijective (fun i : Fin 5 => t.getD i 0) then
+    { toFun := fun i => t.getD i 0
+      invFun := Fintype.bijInv h
+      left_inv := Fintype.leftInverse_bijInv h
+      right_inv := Fintype.rightInverse_bijInv h }
+  else 1
+
+/-- The looked-up map is `conjugatorFun σ τ`:
+`(fun i => (conjugatorTable σ τ).getD i 0) = conjugatorFun σ τ`.  Glue. -/
+private theorem getD_conjugatorTable_fun (σ τ : Perm (Fin 5)) :
+    (fun i : Fin 5 => (conjugatorTable σ τ).getD i 0) = conjugatorFun σ τ :=
+  funext (getD_conjugatorTable σ τ)
+
+/-- Reader of `conjugator`, bijective case: if `conjugatorFun σ τ` is a bijection then
+`conjugator σ τ i = conjugatorFun σ τ i`. -/
+theorem conjugator_apply_of_bijective {σ τ : Perm (Fin 5)}
+    (h : Function.Bijective (conjugatorFun σ τ)) (i : Fin 5) :
+    conjugator σ τ i = conjugatorFun σ τ i := by
+  have h' : Function.Bijective (fun i : Fin 5 => (conjugatorTable σ τ).getD i 0) := by
+    rw [getD_conjugatorTable_fun]; exact h
+  unfold conjugator
+  rw [dif_pos h']
+  exact getD_conjugatorTable σ τ i
+
+/-- Reader of `conjugator`, degenerate case: if `conjugatorFun σ τ` is not a bijection then
+`conjugator σ τ = 1`. -/
+theorem conjugator_of_not_bijective {σ τ : Perm (Fin 5)}
+    (h : ¬ Function.Bijective (conjugatorFun σ τ)) : conjugator σ τ = 1 := by
+  have h' : ¬ Function.Bijective (fun i : Fin 5 => (conjugatorTable σ τ).getD i 0) := by
+    rw [getD_conjugatorTable_fun]; exact h
+  unfold conjugator
+  rw [dif_neg h']
+
+/-! ### Barrington's construction -/
+
+/-- The AND step of [Bar89, Thm 1 proof, p004-b002] for output `σ`: with
+`θ = conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ` and `τᵢ = θ * sigmaᵢ * θ⁻¹`,
+`commutatorProgram P₁ P₂ σ = P₁ τ₁ ++ P₂ τ₂ ++ P₁ τ₁⁻¹ ++ P₂ τ₂⁻¹`, Bar89's `B₁B₂B₁'B₂'`.
+If `P₁ ρ`, `P₂ ρ` recognize `A₁`, `A₂` with output `ρ`, it yields `τ₂⁻¹ * τ₁⁻¹ * τ₂ * τ₁ =
+θ * (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) * θ⁻¹ = σ` on `A₁ ∩ A₂` and the identity elsewhere.
+Deviation: Bar89 takes `B₁, B₂` with outputs `σ₁, σ₂` and conjugates the result (Lemma 1); here
+the outputs `τᵢ` are conjugated in advance, which gives output `σ` directly. -/
+def commutatorProgram (P₁ P₂ : Perm (Fin 5) → BranchingProgram 5 n) (σ : Perm (Fin 5)) :
+    BranchingProgram 5 n :=
+  let θ := conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ
+  P₁ (θ * sigma1 * θ⁻¹) ++ P₂ (θ * sigma2 * θ⁻¹) ++ P₁ (θ * sigma1 * θ⁻¹)⁻¹ ++
+    P₂ (θ * sigma2 * θ⁻¹)⁻¹
+
+/-- Reader of `commutatorProgram`: with `θ = conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ`,
+`commutatorProgram P₁ P₂ σ = P₁ (θ * sigma1 * θ⁻¹) ++ P₂ (θ * sigma2 * θ⁻¹) ++
+P₁ (θ * sigma1 * θ⁻¹)⁻¹ ++ P₂ (θ * sigma2 * θ⁻¹)⁻¹`. -/
+theorem commutatorProgram_eq (P₁ P₂ : Perm (Fin 5) → BranchingProgram 5 n) (σ : Perm (Fin 5)) :
+    commutatorProgram P₁ P₂ σ =
+      P₁ (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ * sigma1 *
+          (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ)⁻¹) ++
+        P₂ (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ * sigma2 *
+          (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ)⁻¹) ++
+        P₁ (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ * sigma1 *
+          (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ)⁻¹)⁻¹ ++
+        P₂ (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ * sigma2 *
+          (conjugator (sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1) σ)⁻¹)⁻¹ := rfl
+
+/-- Barrington's program for a formula `c` with output `σ` [Bar89, Thm 1 proof, p004-b002;
+BV14, Thm 3.5, p014-b001], by recursion on `c` with the output generalized:
+- the literal `x_i` gives `⟨i, 1, σ⟩` and `¬x_i` gives `⟨i, σ, 1⟩` (BV14's order: `map0` first);
+- the constant `node true []` (true) gives `⟨0, σ, σ⟩`, and `node false []` (false) gives
+  `⟨0, 1, 1⟩`; both read variable `0`, hence `[NeZero n]`;
+- a fan-in-1 node gives its child's program;
+- `node true (c₁ :: c₂ :: _)` (`∧`) gives `commutatorProgram (barrington c₁) (barrington c₂) σ`:
+  the children with outputs `τ₁, τ₂, τ₁⁻¹, τ₂⁻¹`, `τᵢ = θ * sigmaᵢ * θ⁻¹`, where `θ` conjugates the
+  commutator `sigma2⁻¹ * sigma1⁻¹ * sigma2 * sigma1` to `σ`;
+- `node false (c₁ :: c₂ :: _)` (`∨`) is De Morgan through Lemma 2 (`complementLast`).
+  *Derivation.* If `B` recognizes `A` with output `ρ`, then `B.complementLast ρ` yields
+  `ρ⁻¹ ∘ B(x)`: the identity on `A` and `ρ⁻¹` off it, so it recognizes `¬A` with output `ρ⁻¹`
+  (C12).  Hence `N c μ := (barrington c μ⁻¹).complementLast μ⁻¹` recognizes `¬c` with output `μ`.
+  The AND step on `N c₁`, `N c₂` with output `σ⁻¹` recognizes `¬c₁ ∧ ¬c₂` with output `σ⁻¹`;
+  applying `complementLast σ⁻¹` gives `¬(¬c₁ ∧ ¬c₂) = c₁ ∨ c₂` with output `(σ⁻¹)⁻¹ = σ`.  Lemma 2
+  keeps lengths, so the length stays `4 · 4^(d−1) = 4^d`.
+Computable (P6-Q13); defined by well-founded recursion on `sizeOf c`, so it is evaluated by
+`#eval`, not by the kernel.  At a node of fan-in above 2 only the first two children are used:
+the theorems assume `c.maxFanin ≤ 2`, where nothing is dropped. -/
+def barrington [NeZero n] : TreeCircuit n → Perm (Fin 5) → BranchingProgram 5 n
+  | .lit ⟨i, true⟩, σ => ⟨[Instr.ofPerm i 1 σ]⟩
+  | .lit ⟨i, false⟩, σ => ⟨[Instr.ofPerm i σ 1]⟩
+  | .node true [], σ => ⟨[Instr.ofPerm 0 σ σ]⟩
+  | .node false [], _ => ⟨[Instr.ofPerm 0 1 1]⟩
+  | .node _ [c], σ => barrington c σ
+  | .node true (c₁ :: c₂ :: _), σ =>
+      commutatorProgram (fun ρ => barrington c₁ ρ) (fun ρ => barrington c₂ ρ) σ
+  | .node false (c₁ :: c₂ :: _), σ =>
+      (commutatorProgram (fun ρ => (barrington c₁ ρ⁻¹).complementLast ρ⁻¹)
+        (fun ρ => (barrington c₂ ρ⁻¹).complementLast ρ⁻¹) σ⁻¹).complementLast σ⁻¹
+termination_by c => sizeOf c

+# Barrington's Theorem 2: branching programs to logarithmic-depth formulas
+
+[Bar89, Thm 2]: a width-`w` branching program of length `l` is recognized by a fan-in-2 circuit
+of depth `O(log l)`, the constant depending on `w`.  The circuit is built here as a fan-in-2
+formula (`BoolCircuit.TreeCircuit`, P6-Q18) that mirrors the three sections of Bar89's proof:
+
+1. *a constant-depth section per instruction* (`Instr.wire`): a map `f : [w] → [w]` is
+   represented by the `w²` wires "`f(i) = j`", and for one instruction each wire is `true`,
+   `false`, `x_var` or `¬x_var`;
+2. *a binary tree of composition circuits* (`wireComp`, `compTree`): the wire
+   `(g ∘ f)(i) = k` is `⋁_j (f(i) = j ∧ g(j) = k)`, a balanced fan-in-2 `∨`
+   (`BoolCircuit.TreeCircuit.balanced`); the instruction list is split at its midpoint;
+3. *a constant-depth acceptance section* (`toFormula`): `⋁_{f ∈ F} ⋀_i (B(x)(i) = f(i))`.
+
+## Main definitions
+
+* `BranchingProgram.Instr.wire`, `wireComp`, `compTree` — the sections 1 and 2.
+* `BranchingProgram.toFormula` — the whole formula (`noncomputable`: it enumerates `F`).
+* `BranchingProgram.topDepth` — the depth constant of the acceptance section.
+
+## Main results
+
+All are statements of the 6a statement phase (targets admitted with `sorry`), except the readers.
+
+* `Instr.wire_eval`, `Instr.depth_wire_le`, `Instr.maxFanin_wire_le` (C17).
+* `wireComp_eval`, `depth_wireComp_le` (C18).
+* `compTree_eval`, `depth_compTree_le`, `maxFanin_compTree_le` (C19).
+* `toFormula_eval` (C20), `depth_toFormula_le`, `maxFanin_toFormula_le` (C21).
+
+## Deviations
+
+* Bar89 builds a circuit; here it is a formula (fan-out one), of size `l^{O(log w)}`, polynomial
+  for fixed `w` (`TreeCircuit.size_succ_le_two_pow`), as ruled by P6-Q18.  It reaches the
+  `DAGCircuit` classes through `Language.InTreeNC.inNC` (`NC1.lean`).
+* The depth constants, left implicit by Bar89, are explicit: `(⌈log₂ w⌉ + 2)·⌈log₂ l⌉ + 1` for the
+  composition tree and `topDepth w = w·⌈log₂ w⌉ + ⌈log₂ w⌉ + 3` on top.
+
+## References
+
+* [Bar89] D. A. Mix Barrington, *Bounded-width polynomial-size branching programs recognize
+  exactly those languages in NC¹*, J. Comput. System Sci. 38(1):150–164, 1989.

+/-! ### The constant-depth section per instruction -/
+
+/-- The wire "`ι` sends `i` to `j`" as a formula of depth at most 1: `true` (`node true []`) if
+both maps send `i` to `j`, the literal `¬x_var` if only `map0` does, `x_var` if only `map1` does,
+and `false` (`node false []`) if neither,
+`ι.wire i j = if ι.map0 i = j then (if ι.map1 i = j then node true [] else lit ⟨ι.var, false⟩)
+else (if ι.map1 i = j then lit ⟨ι.var, true⟩ else node false [])`
+[Bar89, Thm 2 proof, p004-b003: "a constant-depth section to find the function yielded by a each
+instruction", sic]. -/
+def Instr.wire (ι : Instr w n) (i j : Fin w) : TreeCircuit n :=
+  if ι.map0 i = j then
+    if ι.map1 i = j then .node true [] else .lit ⟨ι.var, false⟩
+  else
+    if ι.map1 i = j then .lit ⟨ι.var, true⟩ else .node false []
+
+/-- Reader of `Instr.wire`: `ι.wire i j = if ι.map0 i = j then (if ι.map1 i = j then
+node true [] else lit ⟨ι.var, false⟩) else (if ι.map1 i = j then lit ⟨ι.var, true⟩ else
+node false [])`. -/
+theorem Instr.wire_eq (ι : Instr w n) (i j : Fin w) :
+    ι.wire i j =
+      if ι.map0 i = j then
+        (if ι.map1 i = j then .node true [] else .lit ⟨ι.var, false⟩)
+      else
+        (if ι.map1 i = j then .lit ⟨ι.var, true⟩ else .node false []) := rfl

+/-! ### Composition circuits and the composition tree -/
+
+/-- One composition circuit: from the wires `F i j` ("`f(i) = j`") and `G j k` ("`g(j) = k`"),
+the wire "`(g ∘ f)(i) = k`" is the balanced fan-in-2 disjunction
+`wireComp F G i k = balanced false [node true [F i j, G j k] | j ∈ finRange w]`
+[Bar89, Thm 2 proof, p004-b003: "may be computed by a fixed circuit whose size depends only on
+`w`"]. -/
+def wireComp (F G : Fin w → Fin w → TreeCircuit n) : Fin w → Fin w → TreeCircuit n :=
+  fun i k => TreeCircuit.balanced false ((List.finRange w).map fun j => .node true [F i j, G j k])
+
+/-- Reader of `wireComp`:
+`wireComp F G i k = balanced false ((finRange w).map fun j => node true [F i j, G j k])`. -/
+theorem wireComp_eq (F G : Fin w → Fin w → TreeCircuit n) (i k : Fin w) :
+    wireComp F G i k =
+      TreeCircuit.balanced false ((List.finRange w).map fun j => .node true [F i j, G j k]) :=
+  rfl
+
+/-- The binary tree of composition circuits over an instruction list, split at the midpoint: the
+empty list gives the identity wires (`node true []` on the diagonal, `node false []` off it), one
+instruction gives its wires, and a list `l` of length at least 2 gives
+`wireComp (compTree (l.take (|l| / 2))) (compTree (l.drop (|l| / 2)))` (the first half acts
+first) [Bar89, Thm 2 proof, p004-b003: "a binary tree of composition circuits"].  Defined by
+well-founded recursion on the length. -/
+def compTree : List (Instr w n) → Fin w → Fin w → TreeCircuit n
+  | [] => fun i j => if i = j then .node true [] else .node false []
+  | [ι] => ι.wire
+  | ι₁ :: ι₂ :: l =>
+      wireComp (compTree ((ι₁ :: ι₂ :: l).take ((ι₁ :: ι₂ :: l).length / 2)))
+        (compTree ((ι₁ :: ι₂ :: l).drop ((ι₁ :: ι₂ :: l).length / 2)))
+termination_by l => l.length
+decreasing_by
+  all_goals simp only [List.length_take, List.length_drop, List.length_cons]
+  all_goals omega
+
+/-- Reader of `compTree`, empty list: `compTree [] i j = if i = j then node true [] else
+node false []`. -/
+theorem compTree_nil (i j : Fin w) :
+    compTree ([] : List (Instr w n)) i j =
+      if i = j then .node true [] else .node false [] := by
+  rw [compTree]
+
+/-- Reader of `compTree`, one instruction: `compTree [ι] = ι.wire`. -/
+theorem compTree_singleton (ι : Instr w n) : compTree [ι] = ι.wire := by
+  rw [compTree]
+
+/-- Reader of `compTree`, at least two instructions: with `l' = ι₁ :: ι₂ :: l`,
+`compTree l' = wireComp (compTree (l'.take (l'.length / 2))) (compTree (l'.drop (l'.length / 2)))`.
+-/
+theorem compTree_cons_cons (ι₁ ι₂ : Instr w n) (l : List (Instr w n)) :
+    compTree (ι₁ :: ι₂ :: l) =
+      wireComp (compTree ((ι₁ :: ι₂ :: l).take ((ι₁ :: ι₂ :: l).length / 2)))
+        (compTree ((ι₁ :: ι₂ :: l).drop ((ι₁ :: ι₂ :: l).length / 2))) := by
+  rw [compTree]

+/-! ### The acceptance section -/
+
+/-- **Barrington's Theorem 2, one program** [Bar89, Thm 2, p004-b003]: the formula
+`⋁_{f ∈ F} ⋀_i compTree B.instrs i (f i)` (the constant-depth acceptance section on top of the
+composition tree), `B.toFormula F = balanced false [balanced true [compTree B.instrs i (f i) |
+i ∈ finRange w] | f ∈ F.toList]`; it decides `B.yield x ∈ F` (C20).
+Deviation: built as a formula (fan-out one), not a DAG (P6-Q18); `noncomputable`, because it
+enumerates the `Finset` `F` (`Finset.toList`). -/
+noncomputable def toFormula (B : BranchingProgram w n) (F : Finset (Fin w → Fin w)) :
+    TreeCircuit n :=
+  TreeCircuit.balanced false (F.toList.map fun f =>
+    TreeCircuit.balanced true ((List.finRange w).map fun i => compTree B.instrs i (f i)))
+
+/-- Reader of `toFormula`: `B.toFormula F = balanced false (F.toList.map fun f =>
+balanced true ((finRange w).map fun i => compTree B.instrs i (f i)))`. -/
+theorem toFormula_eq (B : BranchingProgram w n) (F : Finset (Fin w → Fin w)) :
+    B.toFormula F = TreeCircuit.balanced false (F.toList.map fun f =>
+      TreeCircuit.balanced true ((List.finRange w).map fun i => compTree B.instrs i (f i))) :=
+  rfl
+
+/-- The depth of the acceptance section for width `w`:
+`topDepth w = w * Nat.clog 2 w + Nat.clog 2 w + 3` (one level for the leaves of the composition
+tree, `⌈log₂ w⌉ + 1` for the `⋀_i`, `⌈log₂ |F|⌉ + 1 ≤ w·⌈log₂ w⌉ + 1` for the `⋁_f`, since
+`|F| ≤ w^w`) [Bar89, Thm 2 proof, p004-b003: "a constant-depth section at the top"]. -/
+def topDepth (w : ℕ) : ℕ :=
+  w * Nat.clog 2 w + Nat.clog 2 w + 3
+
+/-- Reader of `topDepth`: `topDepth w = w * Nat.clog 2 w + Nat.clog 2 w + 3`. -/
+theorem topDepth_eq (w : ℕ) : topDepth w = w * Nat.clog 2 w + Nat.clog 2 w + 3 := rfl

+depth `≤ d`, then `(wireComp F G i k).depth ≤ d + Nat.clog 2 w + 2` [Bar89, Thm 2 proof, p004-b003].

+**Proof sketch.** `wireComp_eq` and `TreeCircuit.depth_balanced_le`: each `node true [F i j, G j k]`
+has depth `≤ d + 1` (`depth_node`, `maxDepth_cons`), the list has length `w`
+(`List.length_map`, `List.length_finRange`), so the depth is `≤ (d + 1) + ⌈log₂ w⌉ + 1`. -/

+    (hF : ∀ i j, (F i j).depth ≤ d) (hG : ∀ i j, (G i j).depth ≤ d) (i k : Fin w) :
+    (wireComp F G i k).depth ≤ d + Nat.clog 2 w + 2 := by
+  sorry

+/-- **C19.** The composition tree computes the yield: `(compTree B.instrs i j).eval x =

+**Proof sketch.** Strong induction on the length of an instruction list `l`, for the yield of
+`⟨l⟩`: the empty list by `compTree_nil` and `yield_nil`; one instruction by `compTree_singleton`,
+`Instr.wire_eval` and `yield_eq`; otherwise `compTree_cons_cons`, `wireComp_eval` with the
+induction hypothesis for both halves, and `yield_append` on `l = l.take m ++ l.drop m`
+(`List.take_append_drop`, `append_instrs`). -/
+theorem compTree_eval (B : BranchingProgram w n) (i j : Fin w) (x : Fin n → Bool) :
+    (compTree B.instrs i j).eval x = decide (B.yield x i = j) := by
+  sorry

+/-- **C19.** The composition tree has depth `O(log l)`:

+[Bar89, Thm 2 proof, p004-b003].
+Constant (fixed at the statement phase): the leaves have depth `≤ 1` (identity wires and
+`Instr.wire`), and a list of length `l ≥ 2` splits into halves of lengths `⌊l/2⌋ ≤ ⌈l/2⌉` with
+`⌈log₂ ⌈l/2⌉⌉ = ⌈log₂ l⌉ − 1`, each split adding `⌈log₂ w⌉ + 2` levels (C18).

+`compTree_nil`, `compTree_singleton` with `Instr.depth_wire_le` give depth `≤ 1`; for `l ≥ 2`,

+  sorry

+/-- **C19.** The composition tree has fan-in at most 2: `(compTree B.instrs i j).maxFanin ≤ 2`.
+Glue.

+`compTree_nil` (`maxFanin_node`) and `Instr.maxFanin_wire_le`; a composition circuit by

+theorem maxFanin_compTree_le (B : BranchingProgram w n) (i j : Fin w) :
+    (compTree B.instrs i j).maxFanin ≤ 2 := by
+  sorry

+/-- **C20.** Barrington's Theorem 2 formula decides acceptance:

+`B.yield x = f` (`funext`). -/
+theorem toFormula_eval (B : BranchingProgram w n) (F : Finset (Fin w → Fin w))
+    (x : Fin n → Bool) : (B.toFormula F).eval x = decide (B.yield x ∈ F) := by
+  sorry

+/-- **C21.** Depth `O(log l)` with a constant depending on `w`:
+`(B.toFormula F).depth ≤ (Nat.clog 2 w + 2) * Nat.clog 2 B.length + topDepth w`
+[Bar89, Thm 2, p004-b003: "depth `O(log l)`, where the constant depends on `w`"].

+`Finset.card_le_univ`, `Fintype.card_fun`) adds `⌈log₂ |F|⌉ + 1 ≤ w·⌈log₂ w⌉ + 1`

+theorem depth_toFormula_le (B : BranchingProgram w n) (F : Finset (Fin w → Fin w)) :
+    (B.toFormula F).depth ≤ (Nat.clog 2 w + 2) * Nat.clog 2 B.length + topDepth w := by
+  sorry

+theorem maxFanin_toFormula_le (B : BranchingProgram w n) (F : Finset (Fin w → Fin w)) :
+    (B.toFormula F).maxFanin ≤ 2 := by
+  sorry

+# Bounded-width branching programs
+
+The general branching-program model of [Bar89, §1]: an instruction reads one input bit and
+produces a map `[w] → [w]`; a width-`w` program is a finite sequence of instructions, and it
+*yields* on an input the composition of the maps its instructions produce.  A family of programs
+recognizes a language through accepting sets `F_n` of maps.  Permutation programs (every map a
+bijection) are the predicate `IsPermutation`.
+
+## Main definitions
+
+* `BranchingProgram.Instr` — an instruction `⟨var, map0, map1⟩` (BV14's order: `map0` when the
+  bit is `0`), with `Instr.eval`, `Instr.IsPermutation` and `Instr.ofPerm`.
+* `BranchingProgram` — a width-`w` program on `n` inputs (registered model); `length`, `append`
+  (the `++` notation), `yield`, `IsPermutation`, `conj` (Lemma 1's conjugation) and
+  `complementLast` (Lemma 2's change of the last instruction).
+* `BranchingProgramFamily` — a family with accepting sets (registered model); `language`,
+  `IsPolyLength`, `IsPermutation`.
+* `Language.InBWBP`, `Language.InPBP` — the classes BWBP and `PBP_w` (polynomial length).
+
+## Main results
+
+All are statements of the 6a statement phase (targets admitted with `sorry`), except the readers.
+
+* `BranchingProgram.yield_append`, `yield_nil` — the yield composes in program order (C1).
+* `BranchingProgram.yield_conj`, `length_conj`, `length_append` — conjugation (C2).
+* `BranchingProgram.yield_complementLast`, `length_complementLast` — Lemma 2's step (C3).
+* `BranchingProgram.isPermutation_iff` (proved) and the closure lemmas of permutation
+  programs, `IsPermutation.bijective_yield` (C4).
+
+## Conventions and deviations
+
+* **Instruction order.** [Bar89, §1] writes `⟨j, f, g⟩` with `f` used when `x_j = 1`; the fields
+  here follow [BV14, §3.3]'s `(var(t), σ_{t,0}, σ_{t,1})`: `map0` is used when the bit is `0`.
+* **Program order.** [Bar89] writes products left to right (the leftmost map acts first).  The
+  model composes in program order: `(B₁ ++ B₂).yield x = B₂.yield x ∘ B₁.yield x`.  In Mathlib's
+  `Equiv.Perm` product (right factor first) Bar89's word `σ₁σ₂σ₁⁻¹σ₂⁻¹` is
+  `σ₂⁻¹ * σ₁⁻¹ * σ₂ * σ₁`.
+* **Recognition** is by accepting sets, as in [Bar89, §1]: `x ∈ L ↔ B(x) ∈ F_n`.
+
+## References
+
+* [Bar89] D. A. Mix Barrington, *Bounded-width polynomial-size branching programs recognize
+  exactly those languages in NC¹*, J. Comput. System Sci. 38(1):150–164, 1989.
+* [BV14] Z. Brakerski, V. Vaikuntanathan, *Lattice-based FHE as secure as PKE*, ITCS 2014,
+  pp. 1–12; IACR ePrint 2013/541.

+/-- An instruction `⟨var, map0, map1⟩` of width `w` over `n` inputs: read input `var`; apply
+`map0 : [w] → [w]` if it is `0` and `map1` if it is `1` [Bar89, §1, p001-b002].
+Deviation: Bar89 lists the `x_j = 1` map first; the fields follow BV14's
+`(var(t), σ_{t,0}, σ_{t,1})` [BV14, §3.3, p013-b002]. -/
+structure BranchingProgram.Instr (w n : ℕ) where
+  /-- The input bit the instruction reads. -/
+  var : Fin n
+  /-- The map produced when the bit is `0`. -/
+  map0 : Fin w → Fin w
+  /-- The map produced when the bit is `1`. -/
+  map1 : Fin w → Fin w
+
+/-- A width-`w` branching program on `n` inputs: a finite sequence of instructions
+`instrs = [ι₁, …, ι_l]` [Bar89, §1, p001-b002].  Registered model
+(`TCSlib/ComputationalModels.lean`). -/
+structure BranchingProgram (w n : ℕ) where
+  /-- The instructions, in program order. -/
+  instrs : List (BranchingProgram.Instr w n)

+/-! ### Instructions -/
+
+/-- The map an instruction produces on input `x`: `ι.eval x = if x ι.var then ι.map1 else ι.map0`
+[Bar89, §1, p001-b002: "evaluate to `f` if `x_j = 1`, otherwise evaluate to `g`"; BV14 order]. -/
+def Instr.eval (ι : Instr w n) (x : Fin n → Bool) : Fin w → Fin w :=
+  if x ι.var then ι.map1 else ι.map0
+
+/-- Reader of `Instr.eval`: `ι.eval x = if x ι.var then ι.map1 else ι.map0`. -/
+theorem Instr.eval_eq (ι : Instr w n) (x : Fin n → Bool) :
+    ι.eval x = if x ι.var then ι.map1 else ι.map0 := rfl
+
+/-- `ι` is a permutation instruction: both of its maps are bijections,
+`Function.Bijective ι.map0 ∧ Function.Bijective ι.map1` [Bar89, §1, p002-b001]. -/
+def Instr.IsPermutation (ι : Instr w n) : Prop :=
+  Function.Bijective ι.map0 ∧ Function.Bijective ι.map1
+
+/-- Reader of `Instr.IsPermutation`:
+`ι.IsPermutation ↔ Function.Bijective ι.map0 ∧ Function.Bijective ι.map1`. -/
+theorem Instr.isPermutation_iff (ι : Instr w n) :
+    ι.IsPermutation ↔ Function.Bijective ι.map0 ∧ Function.Bijective ι.map1 := Iff.rfl
+
+/-- The instruction `⟨i, σ₀, σ₁⟩` with permutation maps: `Instr.ofPerm i σ₀ σ₁` reads input `i`
+and produces `σ₀` on `0` and `σ₁` on `1` [Bar89, §1, p002-b001; BV14, §3.3, p013-b002].  Its
+field readers are `Instr.ofPerm_var`, `Instr.ofPerm_map0`, `Instr.ofPerm_map1`. -/
+@[simps (config := { isSimp := false })]
+def Instr.ofPerm (i : Fin n) (σ₀ σ₁ : Equiv.Perm (Fin w)) : Instr w n where
+  var := i
+  map0 := σ₀
+  map1 := σ₁
+
+/-- An instruction built from permutations is a permutation instruction:
+`(Instr.ofPerm i σ₀ σ₁).IsPermutation`.  Glue. -/
+theorem Instr.isPermutation_ofPerm (i : Fin n) (σ₀ σ₁ : Equiv.Perm (Fin w)) :
+    (Instr.ofPerm i σ₀ σ₁ : Instr w n).IsPermutation :=
+  ⟨σ₀.bijective, σ₁.bijective⟩

+/-- The length of a program, its number of instructions: `B.length = B.instrs.length`
+[Bar89, §1, p001-b002]. -/
+def length (B : BranchingProgram w n) : ℕ :=
+  B.instrs.length
+
+/-- Reader of `length`: `B.length = B.instrs.length`. -/
+theorem length_eq (B : BranchingProgram w n) : B.length = B.instrs.length := rfl

+/-- Concatenation of programs, `B₁.append B₂ = ⟨B₁.instrs ++ B₂.instrs⟩`: run `B₁`, then `B₂`
+(Bar89's juxtaposition `B₁B₂`, [Bar89, Thm 1 proof, p004-b002]).  It is the `++` notation. -/
+def append (B₁ B₂ : BranchingProgram w n) : BranchingProgram w n :=
+  ⟨B₁.instrs ++ B₂.instrs⟩

+instance : Append (BranchingProgram w n) := ⟨append⟩

+/-- Reader of `append`: `B₁.append B₂ = ⟨B₁.instrs ++ B₂.instrs⟩`. -/
+theorem append_eq (B₁ B₂ : BranchingProgram w n) :
+    B₁.append B₂ = ⟨B₁.instrs ++ B₂.instrs⟩ := rfl

+/-- Reader of the `++` notation: `(B₁ ++ B₂).instrs = B₁.instrs ++ B₂.instrs`. -/
+theorem append_instrs (B₁ B₂ : BranchingProgram w n) :
+    (B₁ ++ B₂).instrs = B₁.instrs ++ B₂.instrs := rfl

+/-- The map `B` yields on `x`: the composition, in program order, of the maps its instructions
+produce, `B.yield x = ι_l.eval x ∘ ⋯ ∘ ι₁.eval x`, computed as the left fold
+`B.instrs.foldl (fun f ι => ι.eval x ∘ f) id`; `yield ⟨[]⟩ x = id` [Bar89, §1, p001-b002:
+"the composition of the functions produced by each of the instructions"].
+Deviation: Bar89's products read left to right; here the first instruction acts first. -/
+def yield (B : BranchingProgram w n) (x : Fin n → Bool) : Fin w → Fin w :=
+  B.instrs.foldl (fun f ι => ι.eval x ∘ f) id
+
+/-- Reader of `yield`: `B.yield x = B.instrs.foldl (fun f ι => ι.eval x ∘ f) id`. -/
+theorem yield_eq (B : BranchingProgram w n) (x : Fin n → Bool) :
+    B.yield x = B.instrs.foldl (fun f ι => ι.eval x ∘ f) id := rfl
+
+/-- `B` is a permutation branching program: every map of every instruction is a bijection,
+`∀ ι ∈ B.instrs, Function.Bijective ι.map0 ∧ Function.Bijective ι.map1`
+[Bar89, §1, p002-b001]. -/
+def IsPermutation (B : BranchingProgram w n) : Prop :=
+  ∀ ι ∈ B.instrs, Function.Bijective ι.map0 ∧ Function.Bijective ι.map1
+
+/-- Conjugation of a program by `θ`: every map `f` of every instruction becomes `θ ∘ f ∘ θ⁻¹`,
+`B.conj θ = ⟨B.instrs.map fun ι => ⟨ι.var, θ ∘ ι.map0 ∘ θ.symm, θ ∘ ι.map1 ∘ θ.symm⟩⟩`
+[Bar89, Lemma 1 proof, p003-b003: "replacing each `σ_i` and `τ_i` by `θσ_iθ⁻¹` and
+`θτ_iθ⁻¹`"]. -/
+def conj (B : BranchingProgram w n) (θ : Equiv.Perm (Fin w)) : BranchingProgram w n :=
+  ⟨B.instrs.map fun ι => ⟨ι.var, θ ∘ ι.map0 ∘ θ.symm, θ ∘ ι.map1 ∘ θ.symm⟩⟩
+
+/-- Reader of `conj`:
+`B.conj θ = ⟨B.instrs.map fun ι => ⟨ι.var, θ ∘ ι.map0 ∘ θ.symm, θ ∘ ι.map1 ∘ θ.symm⟩⟩`. -/
+theorem conj_eq (B : BranchingProgram w n) (θ : Equiv.Perm (Fin w)) :
+    B.conj θ = ⟨B.instrs.map fun ι => ⟨ι.var, θ ∘ ι.map0 ∘ θ.symm, θ ∘ ι.map1 ∘ θ.symm⟩⟩ :=
+  rfl

+/-- Lemma 2's change of the last instruction: the last instruction `⟨i, μ, ν⟩` becomes
+`⟨i, σ⁻¹ ∘ μ, σ⁻¹ ∘ ν⟩`, every other instruction is kept, and the empty program is unchanged:
+`B.complementLast σ = ⟨B.instrs.dropLast ++ [⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩` when
+`ι` is the last instruction [Bar89, Lemma 2 proof, p003-b004: "`⟨i, μσ⁻¹, νσ⁻¹⟩`"].
+Deviation: Bar89's `μσ⁻¹` is read left to right (first `μ`, then `σ⁻¹`), so it is the map
+`σ⁻¹ ∘ μ` here; the definition is total (Bar89 assumes a last instruction). -/
+def complementLast (B : BranchingProgram w n) (σ : Equiv.Perm (Fin w)) :
+    BranchingProgram w n :=
+  match B.instrs.getLast? with
+  | none => B
+  | some ι => ⟨B.instrs.dropLast ++ [⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩
+
+/-- Reader of `complementLast`, by cases on the last instruction:
+`B.complementLast σ = match B.instrs.getLast? with | none => B | some ι => ⟨B.instrs.dropLast ++
+[⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩`. -/
+theorem complementLast_eq (B : BranchingProgram w n) (σ : Equiv.Perm (Fin w)) :
+    B.complementLast σ = match B.instrs.getLast? with
+      | none => B
+      | some ι => ⟨B.instrs.dropLast ++ [⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩ := rfl
+
+/-- `complementLast` on the empty program: `(⟨[]⟩ : BranchingProgram w n).complementLast σ =
+⟨[]⟩`. -/
+theorem complementLast_nil (σ : Equiv.Perm (Fin w)) :
+    (⟨[]⟩ : BranchingProgram w n).complementLast σ = ⟨[]⟩ := rfl
+
+/-- `complementLast` on a program with last instruction `ι`:
+`(⟨l ++ [ι]⟩ : BranchingProgram w n).complementLast σ =
+⟨l ++ [⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩`.  With `complementLast_nil` it covers every
+program (`List.eq_nil_or_concat`). -/
+theorem complementLast_concat (l : List (Instr w n)) (ι : Instr w n) (σ : Equiv.Perm (Fin w)) :
+    (⟨l ++ [ι]⟩ : BranchingProgram w n).complementLast σ =
+      ⟨l ++ [⟨ι.var, σ.symm ∘ ι.map0, σ.symm ∘ ι.map1⟩]⟩ := by
+  rw [complementLast_eq]
+  simp only [List.getLast?_concat, List.dropLast_concat]

+# The branching-program host `evalWith`
+
+A program run on a *state vector* `V : Fin w → α` instead of a single state: one instruction
+sends `V` to the vector whose coordinate `i` collects, through a selector `sel` applied to the
+instruction's input, the sums of the entries that the `0`-branch and the `1`-branch send to `i`
+(the push form).  Folding this step over the instructions in program order is the host
+`BranchingProgram.evalWith`, generic in the selector `sel : β → α → α → α` and in the value type
+`α` (an additive commutative monoid).  It is row H18 of the host registry
+(`machine-library-design.md` §14).  Its consumers are the Boolean semantics (C8: a one-hot state
+stays one-hot at the yield, for every program) and GSW's homomorphic evaluation of a permutation
+program, where `α` is a ciphertext type and `sel` the homomorphic selector.
+
+The push form needs no inverse, so the host is total and computable on the general model of
+[Bar89, §1]; for a permutation instruction each sum has exactly one term and the step is
+[BV14, Eq. (4)]'s pull form (C6).
+
+## Main definitions
+
+* `BranchingProgram.Instr.stepWith` — one instruction on a state vector (push form).
+* `BranchingProgram.evalWith` — the host: `stepWith` folded in program order.
+
+## Main results
+
+All are statements of the 6a statement phase (targets admitted with `sorry`), except the readers.
+
+* `BranchingProgram.evalWith_nil`, `evalWith_append` — readers of the fold (C5).
+* `BranchingProgram.Instr.stepWith_of_isPermutation` — BV14's pull form for a permutation
+  instruction (C6).
+* `BranchingProgram.evalWith_rel` — the step-indexed relational host lemma (C7).
+* `BranchingProgram.evalWith_single` — Boolean semantics for general maps (C8).
+
+## References
+
+* [Bar89] D. A. Mix Barrington, *Bounded-width polynomial-size branching programs recognize
+  exactly those languages in NC¹*, J. Comput. System Sci. 38(1):150–164, 1989.
+* [BV14] Z. Brakerski, V. Vaikuntanathan, *Lattice-based FHE as secure as PKE*, ITCS 2014,
+  pp. 1–12; IACR ePrint 2013/541.

+/-- One instruction on a state vector, push form: coordinate `i` of the new vector is
+`sel (inp ι.var) (∑ j ∈ univ.filter (ι.map0 · = i), V j) (∑ j ∈ univ.filter (ι.map1 · = i), V j)`,
+the selector applied to the instruction's input and to the sums of the entries that the
+`0`-branch and the `1`-branch send to `i`.  Host step; glue generalizing
+[BV14, Eq. (4), p013-b002] from permutations to general maps. -/
+def Instr.stepWith [AddCommMonoid α] (sel : β → α → α → α) (inp : Fin n → β) (ι : Instr w n)
+    (V : Fin w → α) : Fin w → α :=
+  fun i => sel (inp ι.var) (∑ j ∈ univ.filter (fun j => ι.map0 j = i), V j)
+    (∑ j ∈ univ.filter (fun j => ι.map1 j = i), V j)
+
+/-- Reader of `Instr.stepWith`: `ι.stepWith sel inp V i =
+sel (inp ι.var) (∑ j ∈ univ.filter (ι.map0 · = i), V j) (∑ j ∈ univ.filter (ι.map1 · = i), V j)`.
+-/
+theorem Instr.stepWith_apply [AddCommMonoid α] (sel : β → α → α → α) (inp : Fin n → β)
+    (ι : Instr w n) (V : Fin w → α) (i : Fin w) :
+    ι.stepWith sel inp V i = sel (inp ι.var) (∑ j ∈ univ.filter (fun j => ι.map0 j = i), V j)
+      (∑ j ∈ univ.filter (fun j => ι.map1 j = i), V j) := rfl
+
+/-- **The branching-program host** (registry row H18): fold `Instr.stepWith sel inp` over the
+instructions in program order, starting from `V`,
+`B.evalWith sel inp V = B.instrs.foldl (fun U ι => ι.stepWith sel inp U) V`.  Generic in the
+selector `sel` and the value type `α`; its consumers are the Boolean semantics (C8) and GSW's
+homomorphic evaluation (G2).  Glue generalizing [BV14, Eq. (4), p013-b002]. -/
+def evalWith [AddCommMonoid α] (sel : β → α → α → α) (inp : Fin n → β)
+    (B : BranchingProgram w n) (V : Fin w → α) : Fin w → α :=
+  B.instrs.foldl (fun U ι => ι.stepWith sel inp U) V
+
+/-- Reader of `evalWith`: `B.evalWith sel inp V = B.instrs.foldl (fun U ι => ι.stepWith sel inp U)
+V`. -/
+theorem evalWith_eq [AddCommMonoid α] (sel : β → α → α → α) (inp : Fin n → β)
+    (B : BranchingProgram w n) (V : Fin w → α) :
+    B.evalWith sel inp V = B.instrs.foldl (fun U ι => ι.stepWith sel inp U) V := rfl
+

+/-- **C7.** **Step-indexed relational host lemma**: two runs of the host on the same program,

+  sorry

+# Formula arithmetic: carry-save addition
+
+Numbers as little-endian lists of `BoolCircuit.TreeCircuit` formulas, and the carry-save (3:2)
+reduction of many such numbers to two.  A list `U` denotes, under the assignment `x`, the number
+`FormulaArith.val x U = bitsVal (U.map (·.eval x))` (`Adder.lean`'s `bitsVal`).  One carry-save
+step turns three numbers `A, B, C` into two, the bitwise sum `S` (`xor3`) and the shifted
+carries `K` (`maj3`), with `val A + val B + val C = val S + val K` at a cost of four levels of
+depth and none in the bit length.  Applying a layer of steps to the triples of a list of `k`
+numbers, `csaLevels k ≤ 2⌈log₂ k⌉` times, leaves two numbers with the same total.  This is the
+summation step of the decryption formula ([BV11, Lemma 4.5 proof]; r3 §H3.3–H3.4): its depth is
+logarithmic in the number of summands and does not depend on their bit length.
+
+## Main definitions
+
+* `BoolCircuit.FormulaArith.val` — the number a list of formulas denotes.
+* `BoolCircuit.FormulaArith.csaStep` — one 3:2 step `(A, B, C) ↦ (S, K)`.
+* `BoolCircuit.FormulaArith.csaLayer` — one layer of steps over a list of numbers.
+* `BoolCircuit.FormulaArith.csaLevels` — the number of layers needed to reach two numbers.
+* `BoolCircuit.FormulaArith.csaReduce` — the reduction of a list of numbers to two.
+
+## Main results
+
+* `BoolCircuit.FormulaArith.csaStep_val`, `depth_csaStep_le`, `maxFaninL_csaStep_le` — F5:
+  the value equation, depth `+4`, fan-in two (targets).
+* `BoolCircuit.FormulaArith.csaReduce_val`, `depth_csaReduce_le`, `maxFaninL_csaReduce_le`,
+  `csaLevels_le` — F6: the total is kept, depth `4 · csaLevels k` over the inputs (at least
+  `1`), and `csaLevels k ≤ 2⌈log₂ k⌉` (targets).
+
+## References
+
+* [BV11] Z. Brakerski, V. Vaikuntanathan, *Efficient Fully Homomorphic Encryption from
+  (Standard) LWE*, FOCS 2011, pp. 97–106; full version, IACR ePrint 2011/344 (39 pages,
+  2 March 2012), §4.5, Lemma 4.5 and its proof.

+/-! ### One carry-save step (F5) -/
+
+/-- One carry-save (3:2) step on three little-endian numbers: with `L` the longest length and
+every number padded by `const false` to `L` bits, the sum word is the bitwise `xor3`,
+`S_i = xor3 A_i B_i C_i` (`i < L`), and the carry word is the bitwise `maj3` shifted up by one,
+`K = const false :: [maj3 A_i B_i C_i | i < L]`; so `|S| = L` and `|K| = L + 1`.
+`csaStep A B C = (S, K)` with `val A + val B + val C = val S + val K` (`csaStep_val`).
+[BV11, Lemma 4.5 proof, p029-b002]; the carry-save step is the deviation of r3 §H3.4. -/
+def csaStep (A B C : List (TreeCircuit n)) : List (TreeCircuit n) × List (TreeCircuit n) :=
+  ((List.range (max A.length (max B.length C.length))).map fun i =>
+      TreeCircuit.xor3 (A.getD i (TreeCircuit.const false)) (B.getD i (TreeCircuit.const false))
+        (C.getD i (TreeCircuit.const false)),
+    TreeCircuit.const false ::
+      (List.range (max A.length (max B.length C.length))).map fun i =>
+        TreeCircuit.maj3 (A.getD i (TreeCircuit.const false))
+          (B.getD i (TreeCircuit.const false)) (C.getD i (TreeCircuit.const false)))
+
+/-- The carry-save step, written out: with `L = max |A| (max |B| |C|)` and `z = const false`,
+`csaStep A B C = ((range L).map fun i => xor3 (A.getD i z) (B.getD i z) (C.getD i z),
+z :: (range L).map fun i => maj3 (A.getD i z) (B.getD i z) (C.getD i z))`. -/
+theorem csaStep_eq (A B C : List (TreeCircuit n)) :
+    csaStep A B C =
+      ((List.range (max A.length (max B.length C.length))).map fun i =>
+          TreeCircuit.xor3 (A.getD i (TreeCircuit.const false))
+            (B.getD i (TreeCircuit.const false)) (C.getD i (TreeCircuit.const false)),
+        TreeCircuit.const false ::
+          (List.range (max A.length (max B.length C.length))).map fun i =>
+            TreeCircuit.maj3 (A.getD i (TreeCircuit.const false))
+              (B.getD i (TreeCircuit.const false)) (C.getD i (TreeCircuit.const false))) :=
+  rfl

+/-- **F5, value.** One carry-save step keeps the total: for every assignment `x`,
+`val x A + val x B + val x C = val x (csaStep A B C).1 + val x (csaStep A B C).2`.
+[BV11, Lemma 4.5 proof, p029-b002: "The summation (over the integers) can be done in depth
+O(log k + log log p)"].  *Deviation:* the paper does not say how; r3 §H3.4 fixes the carry-save
+(3:2) tree, of which this is one step.

+**Proof sketch.** Write every value through `val_eq` and `bitsVal_eq_prefixVal` as a
+`prefixVal` of its bit sequence, extended to `L + 1` bits by `false` (`prefixVal_congr`; the
+padding `const false` evaluates to `false` by `const_eval`).  Bit by bit, the full-adder
+identity `a + b + c = (a ⊕ b ⊕ c) + 2 · maj(a, b, c)` holds by cases on three Booleans, with
+`xor3_eval` and `maj3_eval` giving the values of `S_i` and `K_{i+1}`; summing it with weights
+`2 ^ i` (induction on the number of bits, `prefixVal_succ`) gives the equation. -/
+theorem csaStep_val (x : Fin n → Bool) (A B C : List (TreeCircuit n)) :
+    val x A + val x B + val x C = val x (csaStep A B C).1 + val x (csaStep A B C).2 := by
+  sorry

+/-- **F5, depth `+4`.** Both output words of a carry-save step lie at most four levels above
+the inputs (counted from at least `1`, the depth of the padding constants):
+`TreeCircuit.maxDepth ((csaStep A B C).1 ++ (csaStep A B C).2) ≤
+max 1 (TreeCircuit.maxDepth (A ++ B ++ C)) + 4`.  [BV11, Lemma 4.5 proof, p029-b002];
+r3's `+4` *(fix)*, settled: `xor3` is `+4`, `maj3` is `+3`, the constant `const false` has
+depth `1`.  No term depends on the bit length.

+**Proof sketch.** `csaStep_eq`.  Each padded input bit `A.getD i (const false)` has depth at
+most `max 1 (maxDepth (A ++ B ++ C))` (`depth_le_maxDepth` for a member, `depth_const` for the

+`K_{i+1}` by that plus `3`, and `depth_const` gives `K_0` depth `1`; a list induction with
+`maxDepth_cons`/`maxDepth_nil` (and `maxDepth` of an append) bounds the maximum. -/

+/-! ### Reduction to two numbers (F6) -/

+/-- One carry-save layer over a list of numbers: every consecutive triple `A, B, C` is replaced
+by the two words of `csaStep A B C`, and a remainder of one or two numbers is kept,
+`csaLayer (A :: B :: C :: Us) = (csaStep A B C).1 :: (csaStep A B C).2 :: csaLayer Us` and
+`csaLayer Us = Us` for `|Us| ≤ 2`.  It sends `k` numbers to `2 ⌊k / 3⌋ + k % 3`.  Glue. -/
+def csaLayer : List (List (TreeCircuit n)) → List (List (TreeCircuit n))
+  | A :: B :: C :: Us => (csaStep A B C).1 :: (csaStep A B C).2 :: csaLayer Us
+  | Us => Us

+/-- A carry-save layer replaces the first triple by its two words:
+`csaLayer (A :: B :: C :: Us) = (csaStep A B C).1 :: (csaStep A B C).2 :: csaLayer Us`. -/
+theorem csaLayer_cons_cons_cons (A B C : List (TreeCircuit n))
+    (Us : List (List (TreeCircuit n))) :
+    csaLayer (A :: B :: C :: Us) = (csaStep A B C).1 :: (csaStep A B C).2 :: csaLayer Us := rfl

+/-- A carry-save layer keeps a list of at most two numbers:
+`Us.length ≤ 2 → csaLayer Us = Us`. -/
+theorem csaLayer_of_length_le_two {Us : List (List (TreeCircuit n))} (h : Us.length ≤ 2) :
+    csaLayer Us = Us := by
+  match Us, h with
+  | [], _ => rfl
+  | [_], _ => rfl
+  | [_, _], _ => rfl
+  | _ :: _ :: _ :: _, h => simp only [List.length_cons] at h; omega

+/-- The number of carry-save layers with fuel `f`: zero once at most two numbers are left,
+`csaLevelsAux (f + 1) k = if k ≤ 2 then 0 else csaLevelsAux f (2 * (k / 3) + k % 3) + 1`. -/
+private def csaLevelsAux : ℕ → ℕ → ℕ
+  | 0, _ => 0
+  | f + 1, k => if k ≤ 2 then 0 else csaLevelsAux f (2 * (k / 3) + k % 3) + 1
+
+/-- The fuel does not matter once it is at least the count. -/
+private theorem csaLevelsAux_fuel :
+    ∀ f g k : ℕ, k ≤ f → k ≤ g → csaLevelsAux f k = csaLevelsAux g k
+  | 0, 0, _, _, _ => rfl
+  | 0, g + 1, k, hf, _ => by
+      obtain rfl : k = 0 := by omega
+      show 0 = if 0 ≤ 2 then 0 else csaLevelsAux g (2 * (0 / 3) + 0 % 3) + 1
+      rw [if_pos (by omega)]
+  | f + 1, 0, k, _, hg => by
+      obtain rfl : k = 0 := by omega
+      show (if 0 ≤ 2 then 0 else csaLevelsAux f (2 * (0 / 3) + 0 % 3) + 1) = 0
+      rw [if_pos (by omega)]
+  | f + 1, g + 1, k, hf, hg => by
+      show (if k ≤ 2 then 0 else csaLevelsAux f (2 * (k / 3) + k % 3) + 1) =
+        (if k ≤ 2 then 0 else csaLevelsAux g (2 * (k / 3) + k % 3) + 1)
+      by_cases hk : k ≤ 2
+      · rw [if_pos hk, if_pos hk]
+      · rw [if_neg hk, if_neg hk,
+          csaLevelsAux_fuel f g (2 * (k / 3) + k % 3) (by omega) (by omega)]
+
+/-- The number of carry-save layers that reduce `k` numbers to at most two: `0` for `k ≤ 2`,
+and `csaLevels (2 * (k / 3) + k % 3) + 1` for `k > 2` (`csaLevels_of_le_two`,
+`csaLevels_of_two_lt`).  Computed with fuel `k`, by structural recursion.  Glue. -/
+def csaLevels (k : ℕ) : ℕ :=
+  csaLevelsAux k k

+/-- No carry-save layer is needed for at most two numbers: `k ≤ 2 → csaLevels k = 0`. -/
+theorem csaLevels_of_le_two {k : ℕ} (h : k ≤ 2) : csaLevels k = 0 := by
+  match k, h with
+  | 0, _ => rfl
+  | f + 1, h =>
+      show (if f + 1 ≤ 2 then 0 else csaLevelsAux f (2 * ((f + 1) / 3) + (f + 1) % 3) + 1) = 0
+      rw [if_pos h]

+/-- More than two numbers need one layer more than their image under a layer:
+`2 < k → csaLevels k = csaLevels (2 * (k / 3) + k % 3) + 1`. -/
+theorem csaLevels_of_two_lt {k : ℕ} (h : 2 < k) :
+    csaLevels k = csaLevels (2 * (k / 3) + k % 3) + 1 := by
+  match k, h with
+  | f + 1, h =>
+      show (if f + 1 ≤ 2 then 0 else csaLevelsAux f (2 * ((f + 1) / 3) + (f + 1) % 3) + 1) =
+        csaLevelsAux (2 * ((f + 1) / 3) + (f + 1) % 3) (2 * ((f + 1) / 3) + (f + 1) % 3) + 1
+      rw [if_neg (by omega), csaLevelsAux_fuel f _ _ (by omega) le_rfl]

+# Formula arithmetic: carry-out and comparison with a constant
+
+For two little-endian formula numbers `U, W` (`FormulaArith.val`), the carry into bit position
+`b` of `U + W` is a formula of depth `2⌈log₂ b⌉ + 3` over the bits, by the generate/propagate
+expansion `carry_b = ⋁_{j < b} (U_j ∧ W_j ∧ ⋀_{j < k < b} (U_k ∨ W_k))` with balanced fan-in-2
+trees; its value is `Adder.lean`'s ripple carry `carryBit`.  The test `c ≤ val U + val W` for a
+constant `c` is the carry-out of `U + W + (2^p - c)` after one more carry-save step.  No
+construction here is a truth table over the bit length: the depth is logarithmic in it
+(r3 §H3.3).
+
+## Main definitions
+
+* `BoolCircuit.FormulaArith.bitAt` — the bit sequence of a formula number under an assignment.
+* `BoolCircuit.FormulaArith.carryOut` — the carry into position `b` of `U + W`.
+* `BoolCircuit.FormulaArith.constBits` — the low `p` bits of a constant, as constant formulas.
+* `BoolCircuit.FormulaArith.geConst` — the comparison `c ≤ val U + val W`.
+
+## Main results
+
+* `BoolCircuit.FormulaArith.carryOut_eval`, `carryOut_eval_le`, `depth_carryOut_le`,
+  `maxFanin_carryOut_le` — F7: the value is `carryBit`, hence `2 ^ b ≤ val U + val W` for
+  `b`-bit numbers; depth `2⌈log₂ b⌉ + 3` over the bits; fan-in two (targets).
+* `BoolCircuit.FormulaArith.geConst_eval`, `depth_geConst_le`, `maxFanin_geConst_le` — F8:
+  the comparison with a constant, its depth and fan-in (targets).
+
+## References

+  (Standard) LWE*, FOCS 2011, pp. 97–106; full version, IACR ePrint 2011/344 (39 pages,

+/-! ### Bit sequences and the carry-out (F7) -/
+
+/-- The bit sequence of a little-endian formula number under the assignment `x`, padded with
+`false`: `bitAt x U j = (U.map (·.eval x)).getD j false`, the bit sequence whose
+`prefixVal` over `|U|` bits is `val x U` (`Adder.lean`'s `bitsVal_eq_prefixVal`).  Glue. -/
+def bitAt (x : Fin n → Bool) (U : List (TreeCircuit n)) (j : ℕ) : Bool :=
+  (U.map fun c => c.eval x).getD j false
+
+/-- The bit sequence of a formula number: `bitAt x U j = (U.map fun c => c.eval x).getD j false`.
+-/
+theorem bitAt_eq (x : Fin n → Bool) (U : List (TreeCircuit n)) (j : ℕ) :
+    bitAt x U j = (U.map fun c => c.eval x).getD j false := rfl
+
+/-- The carry into bit position `b` of `U + W`, by generate/propagate: with `U_j, W_j` the bits
+padded by `const false`, `carryOut U W b = ⋁_{j < b} ⋀ [U_j ∧ W_j, U_{j+1} ∨ W_{j+1}, …,
+U_{b-1} ∨ W_{b-1}]` (bit `j` generates a carry and every higher bit below `b` transmits it),
+the outer `∨` over `j < b` and each inner `∧` as `TreeCircuit.balanced` fan-in-2 trees.  Its
+value is `carryBit` (`carryOut_eval`), its depth `2⌈log₂ b⌉ + 3` over the bits
+(`depth_carryOut_le`).  Glue. -/
+def carryOut (U W : List (TreeCircuit n)) (b : ℕ) : TreeCircuit n :=
+  TreeCircuit.balanced false ((List.range b).map fun j =>
+    TreeCircuit.balanced true
+      (TreeCircuit.and2 (U.getD j (TreeCircuit.const false)) (W.getD j (TreeCircuit.const false)) ::
+        (List.range (b - 1 - j)).map fun k =>
+          TreeCircuit.or2 (U.getD (j + 1 + k) (TreeCircuit.const false))
+            (W.getD (j + 1 + k) (TreeCircuit.const false))))
+
+/-- The carry-out formula written out: with `z = const false`,
+`carryOut U W b = balanced false ((range b).map fun j => balanced true
+(and2 (U.getD j z) (W.getD j z) :: (range (b - 1 - j)).map fun k =>
+or2 (U.getD (j + 1 + k) z) (W.getD (j + 1 + k) z)))`. -/
+theorem carryOut_eq (U W : List (TreeCircuit n)) (b : ℕ) :
+    carryOut U W b =
+      TreeCircuit.balanced false ((List.range b).map fun j =>
+        TreeCircuit.balanced true
+          (TreeCircuit.and2 (U.getD j (TreeCircuit.const false))
+              (W.getD j (TreeCircuit.const false)) ::
+            (List.range (b - 1 - j)).map fun k =>
+              TreeCircuit.or2 (U.getD (j + 1 + k) (TreeCircuit.const false))
+                (W.getD (j + 1 + k) (TreeCircuit.const false)))) := rfl
+
+/-- **F7, value.** The carry-out formula computes the ripple carry into position `b`:
+`(carryOut U W b).eval x = carryBit (bitAt x U) (bitAt x W) b` (`Adder.lean:377`).  Glue
+(r3 §H5.7, F7).  *Statement change:* r3's sketch writes `carryOut U W` with the position `b`
+free; the position is the explicit third argument.
+
+**Proof sketch.** Induction on `b` for the unrolled carry: `carryBit A B (i + 1) =
+(A_i ∧ B_i) ∨ ((A_i ⊕ B_i) ∧ carryBit A B i)` (reader of `carryBit` missing; see the census)
+equals `(A_i ∧ B_i) ∨ ((A_i ∨ B_i) ∧ carryBit A B i)` by cases, and unrolling gives
+`carryBit A B b = ∃ j < b, A_j ∧ B_j ∧ ∀ k, j < k < b → A_k ∨ B_k`.  On the formula side
+`carryOut_eq`, `balanced_eval`, `eval_node_false`/`eval_node_true`, `and2_eval`, `or2_eval`,
+and each padded bit evaluates to `bitAt x U j` (`bitAt_eq`, `const_eval` for the padding,
+`List.getD_map`). -/
+theorem carryOut_eval (U W : List (TreeCircuit n)) (b : ℕ) (x : Fin n → Bool) :
+    (carryOut U W b).eval x = carryBit (bitAt x U) (bitAt x W) b := by
+  sorry

+/-- **F7, the threshold.** For numbers of at most `b` bits the carry into position `b` is the
+test `2 ^ b ≤ U + W`: `U.length ≤ b → W.length ≤ b →
+(carryOut U W b).eval x = decide (2 ^ b ≤ val x U + val x W)`.  Glue (r3 §H5.7, F7).

+**Proof sketch.** `carryOut_eval`, then `prefixVal_add` (`Adder.lean:397`) at `b`:
+`prefixVal A b + prefixVal B b = prefixVal (sumBit A B) b + 2 ^ b · carry`.  Here
+`prefixVal (bitAt x U) b = val x U` (`val_eq`, `bitsVal_eq_prefixVal`, and `prefixVal_congr`
+to extend from `|U|` to `b` bits by `false`), and `prefixVal (sumBit A B) b < 2 ^ b`
+(`prefixVal_lt`), so the carry is `1` exactly when `2 ^ b ≤ val x U + val x W`. -/
+theorem carryOut_eval_le {U W : List (TreeCircuit n)} {b : ℕ} (hU : U.length ≤ b)
+    (hW : W.length ≤ b) (x : Fin n → Bool) :

+  sorry

+/-- **F7, depth.** The carry-out lies `2⌈log₂ b⌉ + 3` levels above the bits (counted from at
+least `1`, the depth of the padding constants):
+`(carryOut U W b).depth ≤ max 1 (TreeCircuit.maxDepth (U ++ W)) + 2 * Nat.clog 2 b + 3`.
+Glue (r3 §H5.7, F7); r3's draft "depth `2⌈log₂(b+1)⌉ + 2`" *(fix)* is settled by this
+construction at `2⌈log₂ b⌉ + 3` over the inputs.

+**Proof sketch.** With `D = max 1 (maxDepth (U ++ W))`: every padded bit has depth `≤ D`
+(`depth_le_maxDepth`, `depth_const`), so every `and2`/`or2` item has depth `≤ D + 1`
+(`depth_and2_le`, `depth_or2_le`).  The inner list for `j < b` has `b - j ≤ b` items, so its
+`balanced true` tree has depth `≤ D + 1 + ⌈log₂ b⌉ + 1` (`depth_balanced_le`,
+`Nat.clog_mono_right`); the outer list has `b` items, so the outer `balanced false` tree adds
+`⌈log₂ b⌉ + 1` more. -/
+theorem depth_carryOut_le (U W : List (TreeCircuit n)) (b : ℕ) :

+  sorry

+/-- **F7, fan-in two.**
+`(carryOut U W b).maxFanin ≤ max 2 (TreeCircuit.maxFaninL (U ++ W))`.  Glue.

+/-! ### Comparison with a constant (F8) -/
+
+/-- The low `p` bits of the constant `c` as constant formulas, little-endian:
+`constBits p c = (range p).map fun j => const (c.testBit j)`, of value `c % 2 ^ p`.  Glue. -/
+def constBits (p c : ℕ) : List (TreeCircuit n) :=
+  (List.range p).map fun j => TreeCircuit.const (c.testBit j)
+
+/-- The constant's bits as formulas:
+`constBits p c = (List.range p).map fun j => TreeCircuit.const (c.testBit j)`. -/
+theorem constBits_eq (p c : ℕ) :
+    (constBits p c : List (TreeCircuit n)) =
+      (List.range p).map fun j => TreeCircuit.const (c.testBit j) := rfl
+
+/-- The comparison of `U + W` with the constant `c`: with `p = max |U| |W| + 1` (so that
+`val U + val W < 2 ^ p`), `geConst U W c` is `const true` for `c = 0`, `const false` for
+`2 ^ p < c`, and otherwise the carry-out at position `p` of the carry-save step of `U`, `W` and
+the `p`-bit constant `2 ^ p - c`:
+`carryOut (csaStep U W (constBits p (2^p - c))).1 (csaStep U W (constBits p (2^p - c))).2 p`,
+since `c ≤ U + W ↔ 2 ^ p ≤ U + W + (2 ^ p - c)`.  Glue (r3 §H3.4 item 3). -/
+def geConst (U W : List (TreeCircuit n)) (c : ℕ) : TreeCircuit n :=
+  if c = 0 then TreeCircuit.const true
+  else if 2 ^ (max U.length W.length + 1) < c then TreeCircuit.const false
+  else
+    carryOut
+      (csaStep U W (constBits (max U.length W.length + 1)
+        (2 ^ (max U.length W.length + 1) - c))).1
+      (csaStep U W (constBits (max U.length W.length + 1)
+        (2 ^ (max U.length W.length + 1) - c))).2
+      (max U.length W.length + 1)
+
+/-- The comparison formula written out: with `p = max U.length W.length + 1`,
+`geConst U W c = if c = 0 then const true else if 2 ^ p < c then const false else
+carryOut (csaStep U W (constBits p (2 ^ p - c))).1 (csaStep U W (constBits p (2 ^ p - c))).2 p`.
+-/
+theorem geConst_eq (U W : List (TreeCircuit n)) (c : ℕ) :
+    geConst U W c =
+      if c = 0 then TreeCircuit.const true
+      else if 2 ^ (max U.length W.length + 1) < c then TreeCircuit.const false
+      else
+        carryOut
+          (csaStep U W (constBits (max U.length W.length + 1)
+            (2 ^ (max U.length W.length + 1) - c))).1
+          (csaStep U W (constBits (max U.length W.length + 1)
+            (2 ^ (max U.length W.length + 1) - c))).2
+          (max U.length W.length + 1) := rfl
+
+/-- **F8, value.** The comparison formula tests `c ≤ U + W`, for all `U`, `W` and `c`:
+`(geConst U W c).eval x = decide (c ≤ val x U + val x W)`.  Glue (r3 §H5.7, F8).
+
+**Proof sketch.** `geConst_eq`, with `p = max |U| |W| + 1`, so `val x U, val x W < 2 ^ (p - 1)`
+(`val_eq`, `bitsVal_eq_prefixVal`, `prefixVal_lt`) and `val x U + val x W < 2 ^ p`.  For
+`c = 0` and for `2 ^ p < c` both sides are constant (`const_eval`).  Otherwise
+`T = 2 ^ p - c < 2 ^ p` and `val x (constBits p T) = T` (`constBits_eq`, `const_eval`,
+`Nat.testBit` and `bitsVal`); `csaStep_val` gives `val S + val K = val U + val W + T`.  The
+carry word `K` has `p + 1` bits, but its top bit is `maj3` of the padding of `U`, `W` (both
+`const false`, as `|U|, |W| ≤ p - 1`) and a bit of `T`, so it is `false` (`csaStep_eq`,
+`maj3_eval`); hence `carryOut_eval` and `prefixVal_add` give the carry into position `p` as
+`decide (2 ^ p ≤ val S + val K)` (`carryOut_eval_le` applied to `K` without its top bit), which
+is `decide (c ≤ val x U + val x W)`. -/
+theorem geConst_eval (U W : List (TreeCircuit n)) (c : ℕ) (x : Fin n → Bool) :
+    (geConst U W c).eval x = decide (c ≤ val x U + val x W) := by
+  sorry
+
+/-- **F8, depth.** The comparison lies `2⌈log₂(max |U| |W| + 1)⌉ + 7` levels above the inputs
+(counted from at least `1`):
+`(geConst U W c).depth ≤ max 1 (TreeCircuit.maxDepth (U ++ W)) +

+r3 names the lemma without a formula).
+
+**Proof sketch.** `geConst_eq`.  The constant cases have depth `1` (`depth_const`).  Otherwise,
+with `D = max 1 (maxDepth (U ++ W))`: the constant bits have depth `1` (`constBits_eq`,
+`depth_const`), so `depth_csaStep_le` bounds both words by `D + 4`, and `depth_carryOut_le` at
+`p = max |U| |W| + 1` adds `2⌈log₂ p⌉ + 3`. -/
+theorem depth_geConst_le (U W : List (TreeCircuit n)) (c : ℕ) :
+    (geConst U W c).depth ≤
+      max 1 (TreeCircuit.maxDepth (U ++ W)) + 2 * Nat.clog 2 (max U.length W.length + 1) + 7 := by
+  sorry

+# Formula arithmetic: the modular interval sum
+
+For public constants `a : Fin M → ℕ` with `a i < q` and an interval `[lo, hi) ⊆ [0, q)`, the
+formula `FormulaArith.modSumInterval a q lo hi` on the bits `x : Fin M → Bool` tests
+`(∑ i, x_i · a_i) mod q ∈ [lo, hi)`.  This is the decryption formula's core
+([BV11, Lemma 4.5]; [BV14, Prop 3.4]): decryption is a binary subset sum of public constants
+followed by an interval test (r3 §H3.2–H3.3).  The construction (r3 §H3.4):
+1. masked constants `x_i · a_i`, each bit the literal `x_i` or the constant `false`;
+2. the carry-save reduction of the `M` summands to two numbers `U, W` with `U + W = S`
+   (`csaReduce`), trimmed to `⌈log₂ M⌉ + ⌈log₂ q⌉` bits (as `S < max M 1 · q`);
+3. for each `j < max M 1` the two-sided test `j q + lo ≤ S < j q + hi` by two comparisons
+   with constants (`geConst`), and
+4. the `∨` over `j` by a balanced fan-in-2 tree.
+
+Its depth is `O(log M + log log q)` with an explicit constant (`modSumDepth`) and no term
+linear in `log q`: no Shannon, DNF or truth-table step touches a `log q`-bit value.
+
+## Main definitions
+
+* `BoolCircuit.FormulaArith.maskedConst` — the number `x_i · a` as a list of formulas.
+* `BoolCircuit.FormulaArith.modSumInterval` — the modular interval-sum formula.
+* `BoolCircuit.FormulaArith.modSumDepth` — its depth bound, in closed form over `csaLevels`.
+
+## Main results
+
+* `BoolCircuit.FormulaArith.modSumInterval_eval` — F9: the formula tests
+  `lo ≤ (∑ i, x_i a_i) % q < hi` (target).
+* `BoolCircuit.FormulaArith.depth_modSumInterval_le`, `modSumDepth_le`,
+  `maxFanin_modSumInterval_le` — F10: depth at most
+  `9⌈log₂ M⌉ + 2⌈log₂(⌈log₂ q⌉ + ⌈log₂ M⌉ + 3)⌉ + 21`, fan-in two (targets).
+
+## References
+
+* [BV11] Z. Brakerski, V. Vaikuntanathan, *Efficient Fully Homomorphic Encryption from
+  (Standard) LWE*, FOCS 2011, pp. 97–106; full version, IACR ePrint 2011/344 (39 pages,
+  2 March 2012), §4.5, Lemma 4.5 and its proof.
+* [BV14] Z. Brakerski, V. Vaikuntanathan, *Lattice-Based FHE as Secure as PKE*, ITCS 2014,
+  pp. 1–12; IACR ePrint 2013/541, §3.1, Proposition 3.4.

+/-- The masked constant `x_i · a` as a `p`-bit little-endian number: bit `j` is the literal
+`x_i` where `a` has a `1` and `const false` elsewhere,
+`maskedConst i a p = (range p).map fun j => if a.testBit j then lit ⟨i, true⟩ else const false`,
+of value `(x i).toNat * (a % 2 ^ p)`.  Glue (r3 §H3.4 item 1). -/
+def maskedConst (i : Fin n) (a p : ℕ) : List (TreeCircuit n) :=
+  (List.range p).map fun j =>
+    if a.testBit j then TreeCircuit.lit ⟨i, true⟩ else TreeCircuit.const false
+
+/-- The masked constant written out: `maskedConst i a p = (List.range p).map fun j =>
+if a.testBit j then TreeCircuit.lit ⟨i, true⟩ else TreeCircuit.const false`. -/
+theorem maskedConst_eq (i : Fin n) (a p : ℕ) :
+    maskedConst i a p =
+      (List.range p).map fun j =>
+        if a.testBit j then TreeCircuit.lit ⟨i, true⟩ else TreeCircuit.const false := rfl
+
+/-- The modular interval-sum formula on `M` bits `x`: with `B = ⌈log₂ q⌉` and
+`w = ⌈log₂ M⌉ + ⌈log₂ q⌉`, let `(U, W) = csaReduce [maskedConst i (a i) B | i < M]` (so
+`U + W = ∑ i, x_i a_i` when every `a i < q`), trimmed to `w` bits; then
+`modSumInterval a q lo hi = ⋁_{j < max M 1} (geConst U W (j q + lo) ∧ ¬ geConst U W (j q + hi))`,
+the `∨` a `balanced false` tree and `¬` the De Morgan `neg`.  It tests
+`lo ≤ (∑ i, x_i a_i) % q < hi` (`modSumInterval_eval`).  [BV11, Lemma 4.5, p029-b001;
+BV14, Prop 3.4, p011-b001]; deviations in `modSumInterval_eval`. -/
+def modSumInterval {M : ℕ} (a : Fin M → ℕ) (q lo hi : ℕ) : TreeCircuit M :=
+  let UW := csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))
+  let U := UW.1.take (Nat.clog 2 M + Nat.clog 2 q)
+  let W := UW.2.take (Nat.clog 2 M + Nat.clog 2 q)
+  TreeCircuit.balanced false ((List.range (max M 1)).map fun j =>
+    TreeCircuit.and2 (geConst U W (j * q + lo)) (geConst U W (j * q + hi)).neg)
+
+/-- The modular interval-sum formula written out: with
+`UW = csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))`,
+`U = UW.1.take w`, `W = UW.2.take w` and `w = Nat.clog 2 M + Nat.clog 2 q`,
+`modSumInterval a q lo hi = balanced false ((range (max M 1)).map fun j =>
+and2 (geConst U W (j * q + lo)) (geConst U W (j * q + hi)).neg)`. -/
+theorem modSumInterval_eq {M : ℕ} (a : Fin M → ℕ) (q lo hi : ℕ) :
+    modSumInterval a q lo hi =
+      TreeCircuit.balanced false ((List.range (max M 1)).map fun j =>
+        TreeCircuit.and2
+          (geConst
+            ((csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))).1.take
+              (Nat.clog 2 M + Nat.clog 2 q))
+            ((csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))).2.take
+              (Nat.clog 2 M + Nat.clog 2 q))
+            (j * q + lo))
+          (geConst
+            ((csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))).1.take
+              (Nat.clog 2 M + Nat.clog 2 q))
+            ((csaReduce (List.ofFn fun i => maskedConst i (a i) (Nat.clog 2 q))).2.take
+              (Nat.clog 2 M + Nat.clog 2 q))
+            (j * q + hi)).neg) := rfl
+
+/-- **F9. The modular interval sum.** For constants `a i < q` and `lo ≤ hi ≤ q`, the formula
+tests whether the binary subset sum `∑ i, x_i · a_i` lies in `[lo, hi)` modulo `q`:
+`(modSumInterval a q lo hi).eval x =
+decide (lo ≤ (∑ i, (x i).toNat * a i) % q ∧ (∑ i, (x i).toNat * a i) % q < hi)`.
+[BV11, Lemma 4.5, p029-b001; BV14, Prop 3.4, p011-b001].  *Deviations:* BV11 computes the bit
+`(ŵ − ⟨v̂, ŝ⟩ mod p) mod 2` by subtracting all multiples of `p` and a selection tree; here the
+output is the interval test that decryption's `decode` is (r3 §H3.2–H3.3, O2), the summands are
+already the masked constants `x_i a_i` (BV11's `ŝ[i]^{(j)} · 2^j v̂[i]`), the summation is the
+carry-save tree (r3 §H3.4), and the reduction mod `q` is an `∨` of two-sided comparisons with
+the constants `j q + lo`, `j q + hi`.  The hypothesis `lo ≤ hi` is r3's; the probe finds the
+equation true without it (`hi ≤ q` and `a i < q` are needed).
+
+**Proof sketch.** (1) Each summand: `val x (maskedConst i (a i) B) = (x i).toNat * a i`
+(`maskedConst_eq`, `eval_lit`, `const_eval`, `val_eq` and `bitsVal` against `Nat.testBit`,
+using `a i < q ≤ 2 ^ B`, `Nat.le_pow_clog`).  (2) `csaReduce_val` and `List.sum_ofFn`:
+`val U + val W = S := ∑ i, (x i).toNat * a i`.  (3) `S < max M 1 · q ≤ 2 ^ w`, so both
+`val U, val W < 2 ^ w` and trimming to `w` bits keeps their values.  (4) `balanced_eval`,
+`eval_node_false`, `and2_eval`, `neg_eval`, `geConst_eval`: the formula is
+`∃ j < max M 1, j q + lo ≤ S ∧ S < j q + hi`.  (5) Arithmetic: with `j = S / q < max M 1`
+this is `lo ≤ S % q < hi`, and no other `j` qualifies since `hi ≤ q` (`Nat.div_add_mod`). -/
+theorem modSumInterval_eval {M : ℕ} {a : Fin M → ℕ} {q lo hi : ℕ} (ha : ∀ i, a i < q)
+    (hlh : lo ≤ hi) (hhq : hi ≤ q) (x : Fin M → Bool) :
+    (modSumInterval a q lo hi).eval x =
+      decide (lo ≤ (∑ i, (x i).toNat * a i) % q ∧ (∑ i, (x i).toNat * a i) % q < hi) := by
+  sorry
+
+/-- The depth bound of the modular interval-sum formula on `M` summands modulo `q`:
+`modSumDepth M q = 4 * csaLevels M + Nat.clog 2 M + 2 * Nat.clog 2 (Nat.clog 2 M + Nat.clog 2 q + 1)
++ 10` (carry-save tree `1 + 4 csaLevels M`, comparison `+ 2⌈log₂(w + 1)⌉ + 7` with
+`w = ⌈log₂ M⌉ + ⌈log₂ q⌉`, the `∧` `+1`, the `∨` over `max M 1` terms `+ ⌈log₂ M⌉ + 1`).
+Glue. -/
+def modSumDepth (M q : ℕ) : ℕ :=
+  4 * csaLevels M + Nat.clog 2 M + 2 * Nat.clog 2 (Nat.clog 2 M + Nat.clog 2 q + 1) + 10
+
+/-- The depth bound written out: `modSumDepth M q = 4 * csaLevels M + Nat.clog 2 M +
+2 * Nat.clog 2 (Nat.clog 2 M + Nat.clog 2 q + 1) + 10`. -/
+theorem modSumDepth_eq (M q : ℕ) :
+    modSumDepth M q =
+      4 * csaLevels M + Nat.clog 2 M + 2 * Nat.clog 2 (Nat.clog 2 M + Nat.clog 2 q + 1) + 10 :=
+  rfl

+/-- **F10, depth.** The modular interval-sum formula has depth at most `modSumDepth M q`, for
+all constants and bounds: `(modSumInterval a q lo hi).depth ≤ modSumDepth M q`.
+[BV11, Lemma 4.5, p029-b001: "fan-in 2 gates and O(log k + log log p) depth"; BV14, Prop 3.4,

+**Proof sketch.** `modSumInterval_eq`.  The masked bits have depth `≤ 1` (`maskedConst_eq`,

+`depth_and2_le` adds `1`, and `depth_balanced_le` over `max M 1` terms adds
+`⌈log₂ (max M 1)⌉ + 1 = ⌈log₂ M⌉ + 1`; the sum is `modSumDepth_eq`. -/
+theorem depth_modSumInterval_le {M : ℕ} (a : Fin M → ℕ) (q lo hi : ℕ) :

+  sorry

+# NAND form of `DAGCircuit`s
+
+A *NAND gate* of `BoolCircuit.DAGCircuit` is the model's own `¬` gate read with at most two
+arguments: `DAGGate.eval` evaluates a `¬` gate as the **negated conjunction** of its arguments
+(`DAGGate.eval_eq`), so `⟨.not, [a, b]⟩` is `NAND(a, b)`, `⟨.not, [a]⟩` is `¬a = NAND(a)` and
+`⟨.not, []⟩` is the constant `false`, the negation of the empty conjunction.  A circuit is in
+*NAND form* when every gate is a NAND gate (`BoolCircuit.DAGCircuit.IsNANDForm`).
+
+The conversion `BoolCircuit.DAGCircuit.toNANDForm` takes every circuit whose gates read at most
+two vertices to NAND form.  It is an instance of the gate-rewriting host
+`BoolCircuit.DAGCircuit.rewrite` (`DAGTransform.lean`), with the gadget
+`BoolCircuit.nandGadget`, built in the style of `BoolCircuit.deMorganGadget` (`DAGFanin.lean`):
+
+| old gate | NAND gadget | gates | depth added |
+|---|---|---|---|
+| `∧[a, b]` | `t := NAND[a, b]`, `NAND[t]` | 2 | 2 |
+| `∨[a, b]` | `NAND[a]`, `NAND[b]`, `NAND[¬a, ¬b]` | 3 | 2 |
+| `∧[a]`, `∨[a]` | `NAND[a]`, `NAND[that]` | 2 | 2 |
+| `∧[]` (true) | `f := NAND[]`, `NAND[f]` | 2 | 2 (absolute) |
+| `∨[]` (false) | `NAND[]` | 1 | 1 (absolute) |
+| `¬[…]` | copied | 1 | 1 |
+
+Every gadget costs at most `fan-in + 2` gates and at most two levels, so the pass gives the
+semantics, depth at most `2 · depth`, and at most `n + 4 · #gates` vertices.
+
+**Disclosures.**
+* NAND-form circuits are **not** `BoolCircuit.DAGCircuit.IsWellFormed`, which demands `¬` gates of
+  fan-in exactly one; lemmas assuming well-formedness (`toTree_eval`, `deMorgan_*`,
+  `binarize_*`) do not apply to them.
+* The names avoid `NAnd`: `BoolCircuit.NAndCircuit` and `BoolCircuit.TreeCircuit.toNAnd`
+  (`Basic.lean`) are the AND-rooted alternating normal form of the LMN development, not NAND
+  gates.
+* No ingested source states that `{NAND}` is a complete basis or gives a conversion; the
+  conversion is glue, motivated by [BV14, Def 2.13, p008-b002] and [BV14, Thm 3.5, p014-b001]
+  ("every Boolean NAND circuit").
+
+## Main definitions
+
+* `BoolCircuit.DAGGate.IsNAND` — a `¬` gate reading at most two vertices.
+* `BoolCircuit.DAGCircuit.IsNANDForm` — every gate is a NAND gate.
+* `BoolCircuit.nandGadget` — the NAND gadget of the table above.
+* `BoolCircuit.DAGCircuit.toNANDForm` — `C.rewrite (nandGadget n) nandGadget_correct hC`.
+
+## Main results
+
+All are statement-phase targets (glue):
+* `BoolCircuit.DAGGate.eval_of_isNAND` (N1) — a NAND gate is the negated conjunction.
+* `BoolCircuit.nandGadget_correct` (N2) — the gadget meets `GadgetCorrect` with depth factor 2.
+* `BoolCircuit.DAGCircuit.toNANDForm_eval`, `toNANDForm_isNANDForm`, `toNANDForm_depth_le`,
+  `toNANDForm_size_le` (N3–N6) — semantics, form, depth `≤ 2 · depth`, size `≤ n + 4 · #gates`.
+
+While N2 is admitted, `sorryAx` reaches `toNANDForm` (whose body passes `nandGadget_correct` to
+`rewrite`) and its consumers through N2 alone.
+

+/-! ## NAND gates and NAND form -/
+
+/-- A *NAND gate*: a `¬` gate (negated conjunction, `DAGGate.eval_eq`) reading at most two
+vertices, `g.IsNAND ↔ g.kind = .not ∧ g.args.length ≤ 2`.  Fan-in 1 is negation and fan-in 0
+the constant `false`.  Not `BoolCircuit.NAndCircuit` (`Basic.lean`, an AND-rooted normal form).
+Glue; motivated by [BV14, Def 2.13, p008-b002; Thm 3.5, p014-b001]. -/
+def DAGGate.IsNAND (g : DAGGate) : Prop := g.kind = .not ∧ g.args.length ≤ 2
+
+/-- The NAND-gate predicate unfolded: `g.IsNAND ↔ g.kind = .not ∧ g.args.length ≤ 2`. -/
+theorem DAGGate.isNAND_iff (g : DAGGate) : g.IsNAND ↔ g.kind = .not ∧ g.args.length ≤ 2 :=
+  Iff.rfl
+
+instance DAGGate.decidableIsNAND : DecidablePred DAGGate.IsNAND := fun g =>
+  inferInstanceAs (Decidable (g.kind = .not ∧ g.args.length ≤ 2))
+
+/-- A circuit is in *NAND form* when every gate is a NAND gate:
+`C.IsNANDForm ↔ ∀ g ∈ C.gates, g.IsNAND`.  Such circuits are not `IsWellFormed`, which demands
+fan-in-1 `¬` gates (disclosed).  Glue; motivated by [BV14, Def 2.13, p008-b002]. -/
+def DAGCircuit.IsNANDForm (C : DAGCircuit n) : Prop := ∀ g ∈ C.gates, g.IsNAND
+
+/-- NAND form unfolded: `C.IsNANDForm ↔ ∀ g ∈ C.gates, g.IsNAND`. -/
+theorem DAGCircuit.isNANDForm_iff (C : DAGCircuit n) :
+    C.IsNANDForm ↔ ∀ g ∈ C.gates, g.IsNAND :=
+  Iff.rfl
+
+instance DAGCircuit.decidableIsNANDForm (C : DAGCircuit n) : Decidable C.IsNANDForm :=
+  inferInstanceAs (Decidable (∀ g ∈ C.gates, g.IsNAND))

+/-- **N1. NAND semantics.** A NAND gate evaluates to the negated conjunction of the values it

+`DAGGate.eval` on NAND gates).

+**Proof sketch.** Rewrite with `DAGGate.eval_eq` (`DAGCircuit.lean`); the kind is `.not` by the
+first component of `g.isNAND_iff`, so the match takes its `.not` branch. -/
+theorem DAGGate.eval_of_isNAND {g : DAGGate} (hg : g.IsNAND) (vals : List Bool) :
+    g.eval vals = !(g.args.all fun a => vals.getD a false) := by

+/-! ## The NAND gadget -/
+
+/-- The NAND gadget, compiling the gate `g` after the gates `gs` (vertex `n + gs.length` is the
+first new gate); it returns the new gate list and the vertex computing `g` (the table of the
+module docstring):
+* `¬[…]`: copied, `(gs ++ [g], n + |gs|)`;
+* `∧[]`: `f := NAND[]`, `NAND[f]`; `∨[]`: `NAND[]`;
+* `∧[a]`, `∨[a]`: `NAND[a]`, `NAND[that]`;
+* `∧[a, b]`: `t := NAND[a, b]`, `NAND[t]`; `∨[a, b]`: `NAND[a]`, `NAND[b]`, `NAND[¬a, ¬b]`;
+* an `∧`/`∨` gate of fan-in above two lies outside the gadget's domain (`nandGadget_correct`
+  assumes fan-in `≤ 2`) and is copied.
+Computable; glue, in the style of `deMorganGadget` (`DAGFanin.lean`). -/
+def nandGadget (n : ℕ) (g : DAGGate) (gs : List DAGGate) : List DAGGate × ℕ :=
+  match g.kind, g.args with
+  | .not, _ => (gs ++ [g], n + gs.length)
+  | .and, [] => (gs ++ [⟨.not, []⟩, ⟨.not, [n + gs.length]⟩], n + gs.length + 1)
+  | .or, [] => (gs ++ [⟨.not, []⟩], n + gs.length)
+  | .and, [a] => (gs ++ [⟨.not, [a]⟩, ⟨.not, [n + gs.length]⟩], n + gs.length + 1)
+  | .or, [a] => (gs ++ [⟨.not, [a]⟩, ⟨.not, [n + gs.length]⟩], n + gs.length + 1)
+  | .and, [a, b] => (gs ++ [⟨.not, [a, b]⟩, ⟨.not, [n + gs.length]⟩], n + gs.length + 1)
+  | .or, [a, b] =>
+    (gs ++ [⟨.not, [a]⟩, ⟨.not, [b]⟩, ⟨.not, [n + gs.length, n + gs.length + 1]⟩],
+      n + gs.length + 2)
+  | .and, _ :: _ :: _ :: _ => (gs ++ [g], n + gs.length)
+  | .or, _ :: _ :: _ :: _ => (gs ++ [g], n + gs.length)
+
+/-- The NAND gadget copies a `¬` gate:

+# Layering NAND-form `DAGCircuit`s
+
+A circuit is *layered* (`BoolCircuit.DAGCircuit.IsLayered`) when every gate sits exactly one level
+above each vertex it reads: `C.depthAt a + 1 = C.depthAt (n + i)` for every argument `a` of gate
+`i`.  Inputs are at level `0` and fan-in-0 gates at level `1`, so a layered circuit evaluates
+level by level.
+
+The conversion `BoolCircuit.DAGCircuit.layerNAND` takes a NAND-form circuit `C` on `n ≥ 1` inputs
+to a layered NAND-form circuit on the `2n` **literals** `x, ¬x` (`BoolCircuit.litInput`), of the
+same depth and function.
+
+**Why literals (the odd-gap finding).** Call a vertex's depth its level.  In a layered NAND
+circuit whose only level-0 vertices are the positive inputs, induction on the level shows that
+every vertex at an even level computes a monotone function and every vertex at an odd level an
+antimonotone one (constants are both; the NAND of antimonotone functions is monotone, and
+conversely).  XOR is neither, so over positive inputs no layering exists in general: an odd gap
+cannot always be padded.  With both literals at level `0` every vertex is available at both
+parities.  Literal inputs are Bar89's "inputs and negated inputs" [Bar89, Thm 1, p003-b002].
+
+**Construction** (computable, by columns in topological order; no NAND-form hypothesis).  Write
+`D := C.depth` and `δ := C.depthAt v`.  Each old vertex `v` with `δ ≤ D` gets a *column* of new
+vertices `v@k`, one for every level `δ ≤ k ≤ D`, with `v@k` at depth exactly `k`:
+* **base** `v@δ`: an input `xᵢ` is input vertex `i`; a gate is a NAND gate over its arguments'
+  copies `a@(δ - 1)`;
+* **parity twin** `v@(δ + 1)`: an input's twin is `NAND(¬xᵢ)`, reading input vertex `n + i`; a
+  gate's twin is the same NAND gate over `a@δ`; a fan-in-0 gate's twin is `NAND(NAND(x₀, ¬x₀))`,
+  which needs `n ≥ 1`;
+* **double-NAND chain** `v@k = NAND(NAND(v@(k - 2)))` for `k ≥ δ + 2`, the inner gate at level
+  `k - 1`.
+
+Every gate is emitted as a NAND gate `⟨.not, args⟩`.  Old vertices deeper than `D` are dead and
+get no column.  The output is `out@D`.  The gate list (`layerGates`) and output vertex
+(`layerOutput`) are definitions; the structure fields of `DAGCircuit` (acyclicity, output in
+range) are the targets N12–N13, as N2 is for `toNANDForm`, so while they are admitted `sorryAx`
+reaches `layerNAND` through them only.
+
+**Column invariant** (the plan of every target's fill): after the fold has processed the old
+vertices `0, …, v - 1`, for every processed `u` with `C.depthAt u ≤ D` and every level
+`C.depthAt u ≤ k ≤ D`, the recorded vertex `u@k` exists below the current vertex count, has depth
+exactly `k`, reads only vertices of depth `k - 1`, and, when `C.IsNANDForm`, has on
+`litInput x` the value of `u` on `x`; the column of `u` has at most `2 (D - C.depthAt u) + 1`
+gates.  It is proved by induction along the fold.
+
+**Not reused.** `DAGCircuit.toLayered` and `TreeCircuit.toLayered` (`LayeredDAG.lean`) map into
+the other model `LayeredCircuit` with one vertex per layer (depth = number of gates) and need
+`IsWellFormed` and no `∨`; the conversion here keeps the `DAGCircuit` model and its depth, and is
+named `layerNAND`, not `toLayered`.  It is not an instance of `DAGCircuit.rewrite`: the input
+count changes and the depth must be exact, not bounded.  The column fold is a construction, not
+a host: its contract does not vary by consumer.
+
+No ingested passage defines layered circuits or a layering conversion: the conversion is glue,
+motivated by the level-by-level evaluation of [BV11, Thm 3.1, p015-b001; Def 3.6, p014-b001]
+("depth-`L` binary arithmetic circuits", an evaluation key whose length depends on `L`).
+
+## Main definitions
+
+* `BoolCircuit.DAGCircuit.IsLayered` — every gate is one level above each vertex it reads.
+* `BoolCircuit.litInput` — the `2n` literals of an input.
+* `BoolCircuit.layerChain`, `BoolCircuit.DAGCircuit.layerAt`, `BoolCircuit.DAGCircuit.layerColumn`,
+  `BoolCircuit.DAGCircuit.layerFold` — the column builder.
+* `BoolCircuit.DAGCircuit.layerGates`, `BoolCircuit.DAGCircuit.layerOutput` — the gates and the
+  output vertex of the layering.
+* `BoolCircuit.DAGCircuit.layerNAND` — the layering conversion.
+
+## Main results
+
+All are statement-phase targets (glue):
+* `BoolCircuit.DAGCircuit.layerGates_acyclic`, `layerOutput_lt` (N12–N13) — the structure fields.
+* `BoolCircuit.DAGCircuit.layerNAND_eval` (N7) — semantics on the literal input.
+* `BoolCircuit.DAGCircuit.layerNAND_isLayered` (N8), `layerNAND_isNANDForm` (N9).
+* `BoolCircuit.DAGCircuit.layerNAND_depth` (N10) — depth preserved exactly.
+* `BoolCircuit.DAGCircuit.layerNAND_size_le` (N11) — size `≤ 2n + (2 · depth + 1) · size`.
+

+/-! ## Layered circuits and literal inputs -/
+
+/-- `C` is *layered*: every gate sits exactly one level above each vertex it reads,
+`C.depthAt a + 1 = C.depthAt (n + i)` for every argument `a` of every gate `i` (inputs at level
+`0`).  Glue, motivated by the level-by-level evaluation of [BV11, Thm 3.1, p015-b001;
+Def 3.6, p014-b001]. -/
+def DAGCircuit.IsLayered (C : DAGCircuit n) : Prop :=
+  ∀ (i : ℕ) (hi : i < C.gates.length), ∀ a ∈ (C.gates[i]).args,
+    C.depthAt a + 1 = C.depthAt (n + i)
+
+/-- Layeredness unfolded: `C.IsLayered ↔ ∀ i (hi : i < C.gates.length), ∀ a ∈ (C.gates[i]).args,
+C.depthAt a + 1 = C.depthAt (n + i)`. -/
+theorem DAGCircuit.isLayered_iff (C : DAGCircuit n) :
+    C.IsLayered ↔ ∀ (i : ℕ) (hi : i < C.gates.length), ∀ a ∈ (C.gates[i]).args,
+      C.depthAt a + 1 = C.depthAt (n + i) :=
+  Iff.rfl
+
+instance DAGCircuit.decidableIsLayered (C : DAGCircuit n) : Decidable C.IsLayered :=
+  @Nat.decidableBallLT C.gates.length
+    (fun i hi => ∀ a ∈ (C.gates[i]).args, C.depthAt a + 1 = C.depthAt (n + i))
+    (fun i hi => List.decidableBAll _ _)
+
+/-- The *literal input* of `x`: the `2n` literals, positive ones first,
+`litInput x = Fin.append x (fun i => !x i)` (Bar89's "inputs and negated inputs"
+[Bar89, Thm 1, p003-b002]). -/
+def litInput (x : Fin n → Bool) : Fin (n + n) → Bool := Fin.append x fun i => !x i

+theorem litInput_eq (x : Fin n → Bool) : litInput x = Fin.append x fun i => !x i := rfl

+/-! ## The column builder -/
+
+/-- The **double-NAND chain**: after the gates `gs` of a circuit with `N` inputs, with `a` and
+`b` the copies of a vertex at the two levels below the next one, append `s` links; link `t`
+appends the inner gate `NAND(a)` (vertex `N + |gs|`) and the outer gate `NAND(NAND(a))` (vertex
+`N + |gs| + 1`), which becomes the copy two levels above `a`.  Returns the new gate list and the
+outer vertices, in level order:
+`layerChain N gs a b 0 = (gs, [])` and `layerChain N gs a b (s + 1) =
+let r := layerChain N (gs ++ [⟨.not, [a]⟩, ⟨.not, [N + |gs|]⟩]) b (N + |gs| + 1) s;
+(r.1, (N + |gs| + 1) :: r.2)`.  Glue (plan section r3 §H3.13). -/
+def layerChain (N : ℕ) : List DAGGate → ℕ → ℕ → ℕ → List DAGGate × List ℕ
+  | gs, _, _, 0 => (gs, [])
+  | gs, a, b, s + 1 =>
+    let r := layerChain N (gs ++ [⟨.not, [a]⟩, ⟨.not, [N + gs.length]⟩]) b (N + gs.length + 1) s
+    (r.1, (N + gs.length + 1) :: r.2)
+
+/-- The empty chain: `layerChain N gs a b 0 = (gs, [])`. -/
+theorem layerChain_zero (N : ℕ) (gs : List DAGGate) (a b : ℕ) :
+    layerChain N gs a b 0 = (gs, []) := rfl
+
+/-- One more link: `layerChain N gs a b (s + 1) = ((layerChain N gs' b (N + |gs| + 1) s).1,
+(N + |gs| + 1) :: (layerChain N gs' b (N + |gs| + 1) s).2)` with
+`gs' = gs ++ [⟨.not, [a]⟩, ⟨.not, [N + |gs|]⟩]`. -/
+theorem layerChain_succ (N : ℕ) (gs : List DAGGate) (a b s : ℕ) :
+    layerChain N gs a b (s + 1) =
+      ((layerChain N (gs ++ [⟨.not, [a]⟩, ⟨.not, [N + gs.length]⟩]) b (N + gs.length + 1) s).1,
+        (N + gs.length + 1) ::
+          (layerChain N (gs ++ [⟨.not, [a]⟩, ⟨.not, [N + gs.length]⟩]) b
+            (N + gs.length + 1) s).2) := rfl
+
+/-- The copy `v@k` recorded in the columns `cols` (column `v` lists `v@δ, v@(δ + 1), …` with
+`δ = C.depthAt v`): `C.layerAt cols v k = (cols.getD v []).getD (k - C.depthAt v) 0`.  Glue. -/
+def DAGCircuit.layerAt (C : DAGCircuit n) (cols : List (List ℕ)) (v k : ℕ) : ℕ :=
+  (cols.getD v []).getD (k - C.depthAt v) 0
+
+/-- The recorded copy unfolded: `C.layerAt cols v k = (cols.getD v []).getD (k - C.depthAt v) 0`. -/
+theorem DAGCircuit.layerAt_eq (C : DAGCircuit n) (cols : List (List ℕ)) (v k : ℕ) :
+    C.layerAt cols v k = (cols.getD v []).getD (k - C.depthAt v) 0 := rfl
+
+/-- One step of the column fold: build the column of the old vertex `v` after the state
+`s = (new gates, columns of 0, …, v - 1)`, over the `n + n` literal inputs.  With `D = C.depth`,
+`δ = C.depthAt v` and `m = n + n + |s.1|` (the next new vertex):
+* `D < δ` (dead vertex): no gate, empty column;
+* `v < n` (input), `D = 0`: column `[v]`;
+* `v < n`, `D ≥ 1`: twin `NAND[n + v]` (vertex `m`), then `D - 1` chain links from `(v, m)`;
+  column `v :: m :: chain`;
+* gate `g = C.gates.getD (v - n) ⟨.not, []⟩`: base `NAND[a@(δ - 1) | a ∈ g.args]` (vertex `m`);
+  if `D = δ` the column is `[m]`; otherwise the twin is `NAND[a@δ | a ∈ g.args]` (vertex
+  `m + 1`), or, when `g.args = []`, `NAND[0, n]` then `NAND[m + 1]` (twin vertex `m + 2`); then
+  `D - δ - 1` chain links from `(m, twin)`; column `m :: twin :: chain`.
+Glue (plan section r3 §H3.13). -/
+def DAGCircuit.layerColumn (C : DAGCircuit n) (s : List DAGGate × List (List ℕ)) (v : ℕ) :
+    List DAGGate × List (List ℕ) :=
+  if C.depth < C.depthAt v then (s.1, s.2 ++ [[]])
+  else if v < n then
