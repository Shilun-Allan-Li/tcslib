# Lossless portable bundle selection

The full record contains every payload at its original logical path. No evidence file has been deleted, altered or shortened. `BUNDLE-FILES.portable.txt` is the smaller publication selection, with paths relative to this packet root. Root preserves the entire full record in R and uses this list for the transport bundle, then adds its canonical pack, tools, anchors and actual library sources.

Only complete files under `inputs/historical-fh10-e0b/` are eligible for omission. A file is omitted only if its entire byte sequence has been directly compared equal to a retained file. Every current13 payload is retained, including current source44, boundaries, controls, metadata, QA and current replay. Every distinct historical byte payload is retained somewhere. Actual historical222 logs, sources, maps and helpers remain fully reconstructible; an aliased file's content is exactly the retained file, not a reconstruction from a proof claim or a new execution. No parsed-metadata regeneration, lossy compression, score filtering or semantic evidence dropping is used.

`BUNDLE-UNIVERSE.json` lists every core logical payload, byte size, SHA256 and retained/alias disposition. `BUNDLE-OMISSION-RECOVERY.json` maps every omitted path directly to one retained path, with its exact bytes/hash and direct equality witness. Every recovery is one hop; no alias depends on another omitted file. All seven transport metadata files and the final MANIFEST/SHA256SUMS are retained separately, outside the core universe to avoid circular hashes. The final full-record manifest still covers all original logical payloads and transport metadata.

To verify an extracted portable selection, run `python3 -I verify_portability.py --root /path/to/extracted-packet`. To materialize the historical logical paths, add `--reconstruct`; the verifier copies the retained bytes to missing omitted paths and verifies every digest/size. It refuses mismatching existing files and unsafe path traversal. It changes only the selected extraction root, and performs no Lean, screen, Git or source-worktree action. During preparation only, `--allow-preparing` permits the not-yet-created final MANIFEST/SHA256SUMS. Do not use that flag as a final-publication check.

The recovered paths are packet-relative logical references. Absolute machine paths recorded in old execution receipts remain historical; this procedure does not recreate the original computer, compiled snapshot or package cache. The manifest/source/tool bindings and original actual execution receipts remain unchanged. Direct equality permits using the same retained text for two historical references without asserting that two different executions were the same execution.

This selection must be regenerated after both actual44 outputs, all pair dispositions and final source QA text have been inserted, then included in the final freeze. Verify actual list bytes plus root supplements and transport framing before publication; target below 90,000,000 bytes, GitHub per-file limit 100 MiB. If the measured complete bundle cannot fit, use two verified companion bundles rather than removing unique evidence. Both actual44 screen results and complete source dispositions are present. The final frozen input includes its MANIFEST/SHA256SUMS; this byte-dedup selection is complete for that private evidence packet. Root still owns canonical publication, its added inputs, gate closure and dispatch.
