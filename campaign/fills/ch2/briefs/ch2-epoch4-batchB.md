## Known pitfalls at this pin

- **The fallback flips sides here.** Malformed strings lie **outside**
  `TAUTOLOGY` (the DNF fallback `⟨[]⟩`, an empty disjunction, is not a
  tautology) — the opposite of `SAT`/`SAT3`, where the fallback is
  satisfiable and malformed strings lie inside. Do not copy the SAT
  membership convention; the pure chain above already absorbs this via
  totality, but your transducer's malformed branch must still output
  exactly `DNF.serialize (CNF.dual ⟨[]⟩)` — the identity is with
  `serialize ∘ dual ∘ decode` on **every** string, not only well-formed
  ones.
- **Empty-term/empty-formula duality** (phase-4 round-1, finding 2): an
  empty *term* evaluates `true` (forces the dual verifier to reject); the
  empty *DNF* evaluates `false`. Keep the two cases distinct in any
  evaluation reasoning.
- The dual flips **only** the polarity bit of each literal record — no
  length change, no index change, no re-numbering. Resist any
  "simplification" of the emitted grammar: the output must decode to
  exactly `CNF.dual (CNF.decode x)`.
- New DNF names only (`DNF.eval`, `DNF.Tautology`,
  `tautology_dual_iff`, …); the colleague's `Formulas.lean` in
  `CircuitComplexity` has an unrelated width-indexed `DNF n` — do not
  import or touch it.
- The emitter-fill pitfall set applies to any clean-call or emit-loop
  consumption: cut `ComputesFunInTime` bounds to actual first halts;
  destructure `0 < C.k`.
- `Tautology.lean` is over the size target under a recorded exception —
  keep all new helpers private and in-file; do not split the module.
