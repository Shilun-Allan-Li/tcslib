If it is invalid, the abstract step halts with a stored negative answer, contradicting the hypothesis that its result is an active configuration; hence this case cannot occur. The return instruction likewise halts, so its active-result hypothesis is impossible.

For an oracle call, the precondition provides distinct arguments and a clean run of the decider on the virtual input formed from the input and register words. The abstract-step equation identifies the oracle-selected successor state, and the compiled machine takes one step to that seam configuration (`sim_call`). Thus choose run length $1$. The only earlier time is $0$, where the machine is at its initial seam configuration. Its register words are the binary words of the register values (`tapeWord_bufferTape`); these words meet the width bound established above. The distinctness, zero head positions, and clean-run condition required by the invariant follow from the precondition. Finally, `rrun_zero` identifies this time-zero configuration with the initial one, completing the invariant check.
