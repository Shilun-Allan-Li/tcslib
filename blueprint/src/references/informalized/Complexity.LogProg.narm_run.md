# Nondeterministic Program Simulation

**Claim.** If every length-$N$ choice sequence makes the register program halt and all configurations before halting satisfy the guard, then some fixed simulation time $T$ keeps every compiled run within the stated tape bounds, makes every length-$T$ run halt with an attainable answer appended to $out$, and realizes every attainable answer on some length-$T$ choice sequence.

**Proof.** Proceed by induction on $N$. For $N=0$, the hypothesis would require the initial configuration to be halted, although it has a live location; thus this case is impossible. For the induction step, the guard holds at the initial configuration (by `NHalts.guard`), so the instruction there meets the preconditions needed for the deterministic simulation results. If it is deterministic, its abstract register-program step either reaches a live configuration or halts with an answer. In the live case, `NHalts.of_det` gives the halting hypothesis for the remaining $N$ choices. The induction hypothesis simulates that suffix; `ndet_live` supplies a fixed-length compiled prefix that stays within the tape bounds and reaches the corresponding next configuration. Concatenating the prefix and suffix gives the required time and preserves both the answer correspondence and the bounds (`NGood.seg`). The equality of attainable answers before and after this deterministic step is given by `nans_det`; it also lets us extend any suffix realizing an answer to a full choice sequence. In the halting case, `ndet_halt` simulates the final deterministic instruction in a fixed number of steps, with the required bounds and final output. Here `nans_det` followed by `nans_halted` identifies the only attainable answer with the instruction's answer, so every length of the compiled run at that time has the desired output, and a padded sequence realizes it. If instead the instruction is a choice between two locations, `NHalts.of_choose` and the induction hypothesis provide simulations for both branches. Let their times be $T_1,T_0$, and choose $T=1+\max(T_1,T_0)$. The initial compiled choice step reaches the corresponding branch configuration (`ncompileTM_stepWith_choose`); `nbox_seam` bounds the initial configuration, and `NGood.choose` combines the branch simulations, extending each to the common time. The answer relation splits into the two branch possibilities by `nans_choose`, so any attainable answer is realized by choosing its branch first and then using that branch's witness, padding the remaining choices after it halts.
