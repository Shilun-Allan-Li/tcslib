# Entering a Procedure Call

**Proof.** The width bound for the call implies that the return-variable index is within the frame, that there are at most $F$ arguments, and that each argument has width at most $F$ (`Stmt.width_call_le_iff`). The code-at hypothesis decomposes the compiled call into its argument code, new-frame code, and jump instruction (`codeAt_call`); the starting bound places the return position within the dispatcher range. First execute the argument code. The argument evaluation result gives each temporary register the corresponding argument value and changes memory only in the temporary region (`effects_argsCode`). Since temporaries lie among scratch addresses (`temps_subset_scratch`), the frame relation can be transported across these writes (`Framed.same`). Next execute the new-frame code. The room bound, strengthened using the strict depth inequality (`Start.room_succ`), supplies enough stack capacity; the new-frame effect establishes the callee's memory relation, places the return position in the designated return cell, and changes memory only in the specified writable region (`effects_newFrame`). The straight-line execution theorem applies to both instruction blocks (`straight_argsCode`, `straight_newFrame`), and their lengths are the argument size and $2F+4$ (`length_argsCode`, `length_newFrame`). Concatenating these runs and taking the final jump, whose negative branch is guaranteed to be representable (`Sizes.inRange_neg_one`), reaches the selected entry. The total number of steps is the call size by its definition. Finally, the argument writes affect only scratch addresses, which are writable, and the new-frame changes are also confined to writable addresses; monotonicity and transitivity of agreement outside a set (`AgreeOutside.mono`, `AgreeOutside.trans`) yield agreement outside the full writable region.
