# Simulation of a memory-augmented program

**Claim.** If a run of a memory-augmented register program halts with answer $b$ after $N$ steps and satisfies the memory guard before halting, then the compiled machine, started from the corresponding configuration, halts with output $out$ followed by $b$; throughout the run its register heads lie between $-1$ and $W$, its decider-work-tape heads have absolute position at most $B$, and its memory head has absolute position at most $P$.

**Proof.** Proceed by induction on the number $N$ of simulated program steps. At each positive stage, the guard at time zero supplies the precondition, register-size bounds, and memory-head bound for the current configuration. Split on the instruction at the current label. If it is a deterministic register instruction, the one-step analysis of the abstract machine (`astep_cases`) shows either that the instruction halts immediately or advances to a new label and register valuation. In the halting case, `mdet_halt` supplies a compiled halting run with the required output and bounds. In the live case, `mdet_live` simulates that instruction through a finite compiled run to the next seam configuration, preserving the bounds; apply the induction hypothesis to the remaining abstract run and concatenate the two compiled runs. If the instruction is a memory instruction, `mmem_step` identifies its one-step abstract update with one compiled-machine step. The current seam configuration satisfies the box bounds by `mbox_mseam`; the next seam configuration satisfies them from the guard at the next abstract time. Apply the induction hypothesis from that updated configuration and concatenate. In both cases, `runFrom_add` justifies concatenating the finite runs, while `runFrom_forall_append` combines their bounds over every intermediate time. The zero-step case cannot have halted from the stated live initial configuration, so it is discharged by the contradiction between that initial state and the halting assumption.
