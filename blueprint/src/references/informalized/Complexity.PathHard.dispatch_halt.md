# Dispatch Halting and Correctness

**Claim.** For a state record whose entries are all at most $B$, the dispatch procedure halts on the paired input with answer true exactly when there is an edge from vertex $u$ to vertex $i$ at radius $s$, and all configurations before halting satisfy the register bound.

**Proof.** Split first on the source vertex $u$, then, where needed, on the target vertex $i$. Each ordinary dispatch instruction takes one step and preserves the guarded register bound; `stepH_of` lifts a halting computation across that step. If $u=0$, targets $i=0,1$ cannot form an edge, by the impossibility of edges from $0$ to vertices below $2$ (`not_edge_zero`); the procedure answers false. For $i\ge 2$, it calls the initial-configuration decider on the code $i-2$ and radius $s$. The oracle answer is exactly membership of that initial-configuration encoding (`orc_init`), which is equivalent to the edge condition in this case (`edge_zero_iff`), so `ans_dec` gives the required answer and halting. If $u=1$, no edge can leave that vertex (`not_edge_one`), and the procedure answers false. Finally, suppose $u\ge 2$. For $i=0$, there is no edge into vertex $0$ (`not_edge_to_zero`), so it answers false. For $i=1$, it calls the accepting-configuration decider on code $u-2$ and radius $s$; the oracle answer matches membership in the accepting language (`orc_acc`), equivalent to the edge condition (`edge_to_one_iff`). For $i\ge 2$, it calls the step decider on codes $u-2$ and $i-2$ with radius $s$. The oracle answer matches the corresponding step relation (`orc_step`), and shifted edge codes characterize that relation (`edge_codes_iff`). In both call cases, `ans_dec` turns this equality of Boolean answers into the claimed halting result. Direct false-answer branches halt by `ans_halt`. The initial register bound supplies the guard for each transition and final answer, giving the bound at every configuration strictly before halting.
