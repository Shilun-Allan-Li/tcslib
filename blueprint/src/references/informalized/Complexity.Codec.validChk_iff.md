# Characterization of Valid Configuration Encodings

**Claim.** A word passes the validity check exactly when it encodes a configuration whose work-tape heads lie within distance $s$ of the origin and whose work tapes are blank outside that distance.

**Proof.** For the forward implication, write $m=2s+1$ and let $A$ be the prefix of $w$ containing the $m$ cell blocks. The length condition ensures $A$ has length $Wm$, so `vScan_eq` describes its scan as the fold of the decoded blocks. No block can fail to decode: if one decoded to none, the option-valued fold would have false validity flag (`foldl_vStepO_none`), contrary to verifier acceptance. Replace each decoded cell by its value, obtaining a sequence $f$. The fold description (`foldl_vStep`) now shows that acceptance enforces exactly one head marker per tape, unique across the cells; it also records which cell contains each tape head. Since the represented input-position bits encode an integer at most $|x|+1$, construct a configuration with that input position and with the state/output marker and tape contents specified by the cells. The cell reconstruction result (`cellOf_mkCfg`) gives both that this configuration lies in the required window and that its cells agree with $f$. The encoded chunks therefore concatenate to $A`: each successful decode recovers the original chunk (`encChunk_of_decChunk`), and the blocks concatenate back to the prefix (`eq_flatten_blocks`). The padding bits represent the chosen input position because every fixed-length bit word is its own padded encoding at its represented value (`eq_padBits`). The length and final-bit conditions show that the remaining suffix is exactly the required terminal true bit. These pieces reconstruct $w$ as the configuration encoding. For the reverse implication, suppose $w$ is the encoding of a configuration in the window. Its length and terminal bit are given by `length_cfgWord` and `cfgWord_last`; the input-position segment is the padded representation described by `cfgWord_pos`, whose value is the input position by `bitsVal_padBits`. The input head is a valid finite position, so this value is at most $|x|+1$. Finally, `vScan_cfgWord` shows the scanned cell prefix is accepted, establishing every clause of the validity check.
