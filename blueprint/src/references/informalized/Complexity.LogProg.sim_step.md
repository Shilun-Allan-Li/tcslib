# One-step call simulation

**Claim.** After one decider step, if the decider remains live, the compiled configuration satisfies the simulation relation again; if the decider halts, the compiled configuration satisfies the return relation.

**Proof.** Unpack the simulation relation, which records the decider state, the current input segment and track position, the phase data, and the correspondence of input heads, register tapes and heads, decider tapes and heads, and output. The segment data bounds the segment index by the number of arguments plus one and hence by the segment-list length (`length_callSegs`). The read-correspondence lemma (`track_read`) identifies both the character test and the virtual symbol seen by the decider; the virtual input-head position therefore gives the same symbol in the decider configuration (`inputSymbol_vpos`). The decider's transition action is then fixed, and its output update is tracked by the list-head identity for appending an optional output bit (`head?_append_toList`). The segment's doubling flag agrees with the flag used by the compiled transition (`segDbl_eq`). The movement correspondence lemma (`gstep_tmove`) identifies the compiled segment, parity, and direction updates with the virtual track move, while `tmove_valid` ensures the new position remains valid. The proof next checks the updated relation component by component: the virtual input head follows from `vpos_tmove`; the real input head follows from `inPos_after`; register tapes are unchanged, and their head positions agree by `regPos_after`, using the no-duplicate-arguments hypothesis; decider tapes and heads are updated by the same decider action; and the output is unchanged on the compiled side. This establishes the new track relation. Finally, if the decider's new state exists, the compiled state is the corresponding simulation state and yields `SimRel`; if its state is absent, the compiled state is the return phase and yields `HaltRel`.
