# Triple-Encoded Input Parsing

**Claim.** For any finite bit string $y$, either it has the stated triple encoding with a canonical binary representation of $s$ whose length is bounded by the binary length of $|y|$, and the step-mode program reaches its $N_1$ copy stage with the specified register values and all earlier registers bounded by $(8W+8)(|y|+1)$; or no such triple encoding exists and the program halts false within the same register bound.

**Proof.** Set $B=(8W+8)(|y|+1)$. The length estimate gives $|y|\le B$. First, the paired-input parsing result (`parse_x`) either identifies $y=\langle x,r\rangle$ and reaches the first parsing stage, or shows that no such pair representation exists and provides a bounded false halt. In the latter case, any triple encoding would give a pair representation, so the second alternative follows. In the former case, the encoding identities show that dropping the first $2|x|+2$ bits leaves $r$, and that $|y|=2|x|+2+|r|$. The parser run (`pr_run`) now splits on whether $r$ decodes. If it does not, the program reaches rejection; no triple encoding can exist, since decoding a nested pair encoding would decode $r$. The bounded rejection run therefore gives the required false halt. If $r$ decodes as $(w,r_2)$, the decoder characterization says $r=\langle w,r_2\rangle$. The parser advances to the next stage, with pointer $2|x|+2|w|+4$. Applying the same argument to $r_2$, if it fails to decode then no triple encoding exists and the accumulated bounded run halts false. If it decodes as $(w',s_0)$, the program advances to the stage for checking the final payload, with pointer $p=2|x|+2|w|+2|w'|+6$; the length and drop identities give $|y|=p+|s_0|$ and $y$'s suffix at position $p$ is $s_0$.

Apply the suffix-processing result (`sw_run`) at this stage. Its success case says exactly that $s_0$ is canonical and its length is at most the binary length of $|y|$; it also supplies bounded $q_1$ and $\mathrm{cap}$ and a run to the $N_1$ copy stage with the indicated registers, where $S$ is the value represented by the canonical suffix. A canonical bit string is the binary expansion of its value, so taking $s=\mathrm{bitsVal}(s_0)$ gives $s_0=\mathrm{bits}(s)$ and hence the required triple shape and length condition. Concatenating the parsing and suffix runs gives the desired reachability. In the failure case, the suffix condition fails; if a triple encoding satisfying the stated binary-length condition existed, uniqueness of pair encoding would force its final suffix to be the canonical binary expansion of its $s$, contradicting that failure. Concatenating the bounded parsing run with the suffix routine's false halt proves the other alternative. Register bounds along these runs are supplied by the component run results and are preserved when runs are concatenated; the endpoint register bounds needed for rejection follow from the register bound invariant.
