**Definition restatements.** These record the code's meaning, including its restrictions, rather than treating the docstrings as specifications already established.

| Definition | Mathematical meaning |
|---|---|
| `Contract` | Data describing a deterministic run from every admissible configuration at one fixed live entry: a natural first-exit time, a complete endpoint, and a closed interval for each work head throughout that run. Exit states form a fixed set of optional states. Nothing is asserted for inadmissible starts. |
| `Positive` | Every admissible start has strictly positive contract time. |
| `trans` | On one machine, concatenate a first-hit run to a fixed intermediate state with a contract starting at that state, provided the final exit set was avoided during the first run. The index link depends on the first index; the second precondition is checked on the actual endpoint. |
| `seq` | In the sum-state seam machine, run the left contract to its single live exit, take one stationary dispatch to the right entry, and run the right contract. Retag the endpoint and final exit set; combine intervals by their hull. |
| `Cfg.bindState` | Replace the optional state by binding it through a partial state map; preserve every other configuration field. A halted configuration stays halted. |
| `inPhase` | Run one tagged phase until its local exit, then dispatch once. Under the global redirect conditions, the resulting first-exit set is the image of all local exits under that redirect, and the head intervals are unchanged. |
| `Cfg.select` | Project an injected bank of work tapes and heads, keep state/input position, and reset the projected output to the empty list. |
| `embed` | Apply the source contract to that normalized selection, forwarding its emitted output after the original host output and leaving unselected tapes and heads unchanged. |
| `clearTM_contract` | Given the indexed word and its two blank boundaries at the selected head, clear its cells in exactly twice its length plus two steps, restore the head, and preserve all other fields except the designated exit state. |
| `Cfg.SameOutside` | Two configurations, possibly with different state types, agree on every work-tape cell outside a given per-tape set. This is an endpoint relation. |
| `Contract.Frames` | Every admissible start and its specified endpoint satisfy that outside-footprint relation for the footprint computed from the index and start. |
| `ReturnContract` | A positive first **return to one fixed anchor**, with complete endpoint and inclusive head intervals; only strictly positive earlier times are forbidden from reaching the anchor. |
| `ReturnContract.release` | Turn such a first return into an ordinary first-exit contract on the fresh-entry release machine, preserving the exact time and intervals. |
| `branch` | Run a two-verdict first phase, dispatch once to the corresponding continuation, and use that continuation's time, endpoint and intervals. Live endpoints carry disjoint tags; halted endpoints share `none`. |

The index-only links in `trans`, `seq` and `branch` are a convenience restriction, not a mathematical necessity. A more general link could also inspect the starting configuration or computed endpoint. Enriching/reindexing the data can express such cases now, but it should not be called the strongest possible general sequencing interface. This is not an additional gate defect for the supplied instances.

**Adversarial instances and the major's obstruction.** All state-only examples below use stationary, silent transitions, so tape/output complications cannot conceal the issue.

1. **Zero duration is intentional.** For an admissible start at `entry`, the structure proves

   \[
   C.time\ i\ d=0\quad\Longleftrightarrow\quad \mathrm{some}(entry)\in exits.
   \]

   Left to right: `runFrom d 0 = d`, then `run` and `exit_mem`. Right to left: if the time were positive, `cut` at zero would exclude the entry from `exits`. Thus an ordinary positive contract cannot have its entry in its exit set. `ReturnContract.pos` and its positive-only cut serve a different purpose; neither a blanket positivity assumption nor deletion of the zero-time cut is appropriate.

2. **`trans.hX` cannot be dropped.** Use the state trace

   \[
   a\longmapsto q\longmapsto b\longmapsto q.
   \]

   The first contract reaches its sole exit `b` for the first time at time 2. The second starts at `b` and reaches its exit `q` at time 1. Their proposed total time is `2 + 1 = 3`, but the composite already reached `q` at time 1. Both operand contracts are valid; the omitted `hX` is exactly what fails.

3. **Same-phase redirects can be safe or unsafe.** In one phase, let the source contract run from `a` to local exit `b` in one step. Redirect `b` to a new state `c` in that same phase. The host trace is `a, b, c`; the target is first reached at time 2, so the desired contract is valid although `q.1 ≠ p` is false. Redirecting `b` back to `a` instead makes the target an exit already at time zero. The required condition is target avoidance, not phase inequality itself.

4. **A genuine `RecordRun` need not be a first-exit/first-return contract.** Take a zero-work-tape machine with distinct states `a`, `yes`, `no`, staying at `a` forever. A segment of length 2 from `a` to itself satisfies `RecordRun`: neither verdict is visited and its head condition is empty. To package this segment as a positive ordinary `Contract`, its endpoint would require `some a ∈ exits`, contradicting the cut at zero. To package it as a `ReturnContract` of time 2, its cut at time 1 would require `some a ≠ some a`. Changing the index cannot repair either contradiction while preserving the same start, time and endpoint. This disproves a general direct conversion; it does not assert that every concrete CfgRecord segment is unconvertible.

5. **Return-or-escape rounds require more than a returning contract.** Let the two round exits be its entry anchor `a` and a distinct escape `e`, as in `rt_find_round_entry`. For positive time, an ordinary contract with exits `{some a, some e}` fails its zero-time cut. A `ReturnContract` at `a` excludes every escaping endpoint. On the returning subcase it also does not, by itself, exclude an earlier visit to `e`. A split into return/escape specifications can work only if it retains the extra cut obligations. In particular, `counterLoopTMVia_run_escape` needs the final escaping round, not just the returning prefix.

6. **Intervals do not preserve joint trajectories.** The head vectors `(0,0)` and `(1,1)` fit the coordinate intervals `[0,1]`, as does `(0,1)`. A relation asserting equality of the two coordinates accepts the first two and rejects the third. Hence separate interval bounds cannot imply `counterSpan`'s arbitrary head-vector relation or replace a theorem giving one shared body-round/time witness for all heads. Such relational information must be carried separately when preserving those existing conclusions.

7. **Output normalization is observable at the specification level.** A one-step silent source contract can require initial output `[true]` and preserve that output. It has admissible starts. Its `embed` along the identity tape selection tests the same precondition on output `[]`, so the transported precondition is false for every host. This is consistent with the implemented normalized-call policy, but rules out a claim of unrestricted precondition-preserving transport.

I also checked the empty-word clear case: its time is `2`, its write footprint is empty, and its selected-head interval is `[initial head − 1, initial head]`. For zero tapes, envelope/frame claims are correctly empty; they supply no hidden tape-existence guarantee. With both branches halting, `none` is shared but `live` excludes premature collapse into it. These cases reveal no false theorem in the proposal.

Suggested permanent sanity lemmas are the zero-time equivalence, positivity of `seq`/`inPhase`/`branch`/`release`, and preservation of specified frame footprints under composition. A regression example for the proposed mixed-round interface should cover both return and escape under one fixed machine.

Parenthesized integer pairs are work-head position vectors. Other identifiers are the supplied Lean declarations or their existing parameters.
