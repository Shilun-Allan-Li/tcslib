**Definitions restated before source docstrings, and interface assessment.** These are the mathematical readings recorded from comment-stripped source, expanded here to make the audit independently understandable. Write `n` for input length, `S(n)` for a space allowance, `W(n)` for register digit width, `P(n)` for a memory-head radius, and `σ` for a finite Boolean choice word. An ARM register contains a natural number represented by the bits of its value plus one. A “seam” is the compiled configuration representing a program configuration with the oracle workspace reset.

1. **NARM operational definitions.** `NIns` adds a binary jump to ordinary ARM instructions. `nastep` leaves halted configurations fixed, executes a deterministic instruction independently of the choice bit, or jumps to the selected label without changing registers or the answer. `narun` consumes one bit per abstract step. `NHalts ... N` says that every word of exactly length `N` ends with no live label, and that every earlier live prefix satisfies the guard. `NAns ... N b` merely says that some such word has result `some b`; it does not assert halting by itself. `NTerm` is an inductively well-founded all-successors termination condition, `NAcc` is existential successful termination, and `NSem` combines termination with the intended acceptance proposition. Its uniform-bound theorem is justified by finite binary branching, not by a premise about only the accepting branch.

2. **NARM compilation and space.** `ncompileTM` uses the deterministic compiler of the false-return skeleton and replaces precisely the start states of `choose` labels by one compiled jump. Away from those states its transition agrees with the appropriate deterministic skeleton, including call/return states. Real oracle machines and the call preconditions remain in the hypotheses; oracle answers are not free computational power. Starting at a live label with no result, every abstract stopping instruction supplies a Boolean, so the compiled terminal output is the previous output followed by that Boolean. `narm_space` gives one finite compiled budget `T` for every choice word, space at most `m*(W+2) + kD*(2*B+1)` on every length-`T` word, and existential acceptance exactly when `NAns ... N true` holds. This matches the halting, all-branch space, and acceptance clauses of `FinNDTM.DecidesInSpace`, up to orienting the final equivalence. The class bridges quantify over all inputs and use one compiled finite machine.

3. **Polynomial-width ARM.** There is no second operational machine or compiler. `arm_decides_space` allows digit width bounded by `C*S(n)`, assumes `S(n) ≥ 1`, and requires each real oracle decider's space bound at every length `v ≤ 2*n+2+m*(2*W(n)+2)` to be at most `C*S(n)`. The query bound uses the distinct-argument-register requirement, hence at most `m` encoded registers. The PSPACE instance allows polynomial digit length in the original input length plus one, and polynomial-space oracle languages on their own query lengths. Those queries have polynomial length in the original input. The value variant permits values at most `2^(C₀*(n+1)^c₀)` and absorbs the constant extra digits in `bits(value+1)`. It does not mistake a polynomial bound in the query length for a bound in an unbounded external parameter.

4. **MARM and its time bridge.** MARM adds an integer-indexed Boolean memory and an integer head. The extra instructions read, set to true, or move one cell left/right. There is no reset-to-false instruction. Compilation adds one initially blank memory tape; its reachable symbols are blank or true. `MHalt` requires actual termination with the specified answer and the guard before each live step. In `runFrom_count_eq`, the write action's outer `none` means “do not write”; `some none`, which would erase a cell, is forbidden. The theorem begins at the TM's actual initial configuration, assumes a finite halting time, and bounds all heads through that time.

   With `K` ordinary tapes, the count is

   `(card St + 1) * (n + 2) * 3^(K*(2*B+1)) * (2*B+1)^K * (2*P+1) * (2*P+2)`.

   The factors count state, input position, ordinary tape symbols, ordinary heads, memory head, and number of true memory cells. Cardinality does not identify arbitrary memories. Along this run the true-cell sets are nested; equal cardinality then implies equal memory. Together with the remaining core data, a repeated live configuration would force indefinite deterministic repetition, contradicting halting. Output can be omitted from the transition-driving core because transitions do not read it. The compiled machine in `marm_dtime` is fixed for all inputs, with time `2^(C*(W(n)+logSpace(n)+1))*(P(n)+1)^2`. In `ExpBFS`, `W = O(S+1)` and `P = 2^O(S+1)`, so this is `2^O(S+1)`; `S ≥ logSpace ≥ 1` makes this the intended exponential-space-to-time bound.

5. **Codec and graph interface.** `InWin s C` requires both every work head and every nonblank work cell to lie in `[-s,s]`. `cfgWord` serializes `2*s+1` fixed-width chunks, with the control/output-summary information in the first chunk and tape symbols/head flags at their designated positions, then a padded input-head field and a final true sentinel. `cfgCode` is its binary value. It represents `coreSum`: state, input head, complete work tapes and heads, and an output summary distinguishing empty output, exactly `[true]`, and all other outputs. On bounded configurations the window determines the complete tapes because all outside cells are blank. The last output class cannot become accepting by appending more symbols, so the quotient respects transitions and acceptance.

   Equality of `coreSum` always gives equal words; the converse needs both `InWin` hypotheses. `decodeCfg` is noncomputable choice of a bounded representative, with equality only of `coreSum`, not a literal inverse for every output list. The three single-code languages require the exact canonical encoding `⟨x,⟨bits c,bits s⟩⟩`; the step language requires `⟨x,⟨bits c,⟨bits c',bits s⟩⟩⟩`. Validity means a bounded representative exists; initialization means the initial code; acceptance means a bounded halted representative with output exactly `[true]`; a step witnesses one actual `CfgStep` between bounded representatives. These tests are implemented by logspace ARM deciders for each fixed machine table. They do not execute `Classical.choose` as an algorithm. `mem_iff_codeChain` needs a large enough window to produce the accepting chain; its reverse direction follows from `mem_of_codePath` without that size hypothesis.

6. **`compile_correct_from`.** The source configuration is an arbitrary configuration of the existing register-tape program `RProg`, not necessarily an initial blank one. `seam` embeds its original tapes, heads, state, input head, and output and supplies blank, zero-position oracle work tapes. A bounded program run with `CallOK` at every call has a finite compiled run to the corresponding endpoint seam and preserves the specified register and oracle head envelopes. This makes splicing between nondeterministic choices meaningful. It asserts existence of a compiled duration, not an unproved uniform time estimate. The old initial-configuration theorem is its natural specialization.

**Adversarial instantiations.** These are source-level mathematical checks, not newly executed Lean tests. They cover fidelity, trivialization, boundary hypotheses, and duplication.

| Case | Attempt and result |
|---|---|
| 1. Genuine NARM self-loop | Use one label `l` with `A l = choose l l`, starting live. Every finite run remains live, including the empty word, so no `N` satisfies `NHalts`. Merely making two destinations equal is insufficient: if they lead to a different label containing `ret true`, a two-step bound works. |
| 2. An early-halted branch | One choice branch returns immediately and the other after several steps. Padding to their common abstract bound preserves the early answer because halted configurations are fixed. Several words can describe the same early branch; this is harmless for existential acceptance, and is not a claim that padded words are counted once. The compiled bound likewise accommodates both durations. |
| 3. Answerless terminal input to the abstract predicate | `NHalts` can hold of `(none,v,none)` while neither answer predicate holds. That is a real behavior of the standalone predicate, not a counterexample to the bridges: their initial state is `(some l₀,0,none)`, and every reachable stopping instruction sets a result. |
| 4. Empty input and zero width | `logSpace 0 = 1`; each `bits(v+1)` has at least one digit. Polynomial bounds with `n+1` can accommodate zero registers' values on empty input. With a positive number of registers, a live zero-width guard is unsatisfiable, honestly so. With zero registers it is vacuous and can describe a real constant-output machine; no complexity class collapses. |
| 5. Codec radius zero and out-of-window collision | Compare a bounded configuration with one differing only by a nonblank cell at position 1, keeping heads at 0. Their radius-zero words can agree although the latter is not `InWin`. The numeric word may belong to `validLang` because it also represents the bounded configuration. No theorem asserts validity of the unbounded original or injectivity outside the window. |
| 6. Output-summary collision | Outputs `[false]` and `[true,true]` share the dead summary but are not accepting, including in a halted state. Neither can become exactly `[true]` by appending output. Empty output and exactly `[true]` remain distinct. No false accepting edge is created by this quotient. |
| 7. Noncanonical code fields | Add a redundant high zero to a natural-number field, remove a pair separator, or provide an invalid chunk/sentinel. The four languages require exact `Nat.bits` and exact pair encodings plus their semantic witnesses; malformed representations are not extra inputs in the languages. Their deciders include the relevant parsing/canonicality checks. |
| 8. Equal counts, later escape | Suppose reachable counts at `s` and `s+1` agree but a run first exits at a later radius. The first edge leaving the smaller window has its predecessor reachable there and its successor within `s+1`. Injective recoding plus equal finite cardinalities gives a representative of that successor already in the smaller window, contradicting first exit. Incorrect nondeterministic count guesses reject; the initial reachable set is nonempty, so the initial zero sentinel is not a false stopping certificate. |
| 9. MARM at `P=0`; attempted erase | A machine may stay at cell 0, set it true, and halt. The memory factor is `1*2`, not zero.
