/-!
# Stage 2: the word-RAM-to-`FinTM` simulation (statement draft; PROG-4, with PROG-3)

**Status: a sorried statement draft, not for landing.** It lives in the draft namespace
`TCSlib.Draft.Stage2` and imports only modules that exist. Everything new about the RAM is
defined here by *wrapping* the vendored word RAM (`WordRAM.Instr`, `WordRAM.Cfg`,
`WordRAM.effect`), never by editing it (design §15a, §15c, §16b; backlog PROG-3, PROG-4).

A word-RAM program `P` (`XProgram`: the nine vendored instructions plus `rdIn`, `emit`, `coin`,
`half`) is run on an input `x`, a coin stream `ρ` and a word size `W`. Stage 2 says that one
`FinTM Bool` simulates it, instruction by instruction, with a polynomial time overhead and a
space bound linear in (cells touched) × (word size):

* time `TW n + A·(t + 1)·(f·(W + 1) + W² + n + 1)`, space `SW n + A·(f·(W + 1) + W + log n + 1)`,

where `n = |x|`, `t` bounds the RAM's steps, `f` the number of distinct cells it touches,
`W = W(n)` is computed by a machine within time `TW` and space `SW`, and `A` depends on `P`
only. The nondeterministic form is the same with one `FinNDTM` choice step per `coin`, under
bounds that are uniform over all coin streams.

## Deviations from the §15a draft shape (reasons in `NOTES.md`)

* **No separate address width `a`.** Addresses in this RAM are words (`load`/`store` use
  `(m j).toInt`), and the immediate addresses are constants of `P`, so a table entry has
  `W + O_P(1)` bits; `f·(W + a)` becomes `f·(W + 1)` with the constant in `A`.
* **The input seek costs `O(n + W)`, not `O(n·log n)`.** R8.5b (`Turing.exists_inputSeekTM`)
  seeks position `p` within `C·(|w| + pos + p + 1)` steps for a position word `w`; here
  `|w| ≤ W` and `pos, p ≤ n + 1`.
* **The word size enters additively.** Computing `W(n)` costs the witness's own `TW n` steps
  and `SW n` cells, once.

## Main definitions

* `XInstr`, `XProgram`, `XCfg`, `xstep`, `XSteps`: the draft extended word RAM.
* `baseTouches`, `XInstr.touches`, `XStepsIn`, `StepsIn`: cells touched along a run.

/-! ## The draft extended word RAM

Copied from the vendored layer: nothing is copied verbatim. `xstep` restates the match of
`WordRAM.step` (`TCSlib/Programs/WordRAM/Steps.lean:116-129`) for the nine vendored
instructions, but routes the six straight-line ones through the vendored `WordRAM.effect`
(`Steps.lean:249-257`) instead of copying their arms; `XSteps` restates `WordRAM.Steps`
(`Steps.lean:134-136`) with the input and the coin stream as parameters. -/

/-- The instructions of the draft extended word RAM: the nine instructions of the vendored
`WordRAM.Instr`, and four more. `rdIn i j` sets `[i]` to the input bit at position `[j]` (as
`0` or `1`; `0` off the input); `emit i` appends the bit "`[i]` is nonzero" to the output;
`coin i` sets `[i]` to the next coin (as `0` or `1`) and consumes it; `half i j` sets `[i]` to
`[j]` shifted right by one place, the sign kept (`⌊[j] / 2⌋`). [AFM26, `EndStatement.lean`],
extended per design §15c. -/
inductive XInstr : Type where
  | base (i : Instr)
  | rdIn (i j : ℤ)
  | emit (i : ℤ)
  | coin (i : ℤ)
  | half (i j : ℤ)

/-- A program of the draft extended word RAM: its instructions, at positions `0, 1, 2, …`. -/
abbrev XProgram : Type := List XInstr

/-- A configuration of the extended RAM: the vendored configuration (position and memory), the
bits emitted so far, and the number of coins consumed so far. The input and the coin stream are
not part of it; they are parameters of a run. -/
structure XCfg (W : ℕ) extends WordRAM.Cfg W where
  /-- The bits emitted so far, oldest first. -/
  out : List Bool
  /-- The number of coins consumed so far. -/
  rd : ℕ

/-- The word of the input bit at position `p`: `1` if `0 ≤ p` and the bit there is `true`,
`0` otherwise (in particular off the input). -/
def inBitWord (W : ℕ) (x : List Bool) (p : ℤ) : BitVec W :=
  if 0 ≤ p ∧ x.getD p.toNat false = true then 1 else 0

/-- The word of a coin: `1` for `true`, `0` for `false`. -/
def coinWord (W : ℕ) (b : Bool) : BitVec W := if b then 1 else 0

/-- One step of the extended RAM on input `x` with coin stream `ρ`: the next configuration, or
the verdict. The nine vendored instructions behave as in `WordRAM.step` and leave the output
and the coins alone; past its end the program rejects. The coin read is `ρ.getD rd false`, so a
stream that runs out reads `false`. -/
def xstep {W : ℕ} (P : XProgram) (x ρ : List Bool) (c : XCfg W) : XCfg W ⊕ Bool :=
  let m := c.mem
  match P.getD c.pc (.base .reject) with
  | .base .accept => .inr true
  | .base .reject => .inr false
  | .base (.bltz i l) => .inl { c with pc := if (m i).toInt < 0 then l else c.pc + 1 }
  | .base ins => .inl { c with pc := c.pc + 1, mem := WordRAM.effect ins m }
  | .rdIn i j =>
    .inl { c with pc := c.pc + 1, mem := Function.update m i (inBitWord W x (m j).toInt) }
  | .emit i => .inl { c with pc := c.pc + 1, out := c.out ++ [decide (m i ≠ 0)] }
  | .coin i =>
    .inl { c with pc := c.pc + 1, mem := Function.update m i (coinWord W (ρ.getD c.rd false)),
                  rd := c.rd + 1 }
  | .half i j => .inl { c with pc := c.pc + 1, mem := Function.update m i ((m j).sshiftRight 1) }

/-- `XSteps P x ρ n c c'`: exactly `n` steps of `P` on input `x` and coin stream `ρ` lead from
`c` to `c'`, none of them a verdict. The extended counterpart of `WordRAM.Steps`. -/
def XSteps {W : ℕ} (P : XProgram) (x ρ : List Bool) : ℕ → XCfg W → XCfg W → Prop
  | 0, c, c' => c = c'
  | n + 1, c, c' => ∃ c₁, xstep P x ρ c = .inl c₁ ∧ XSteps P x ρ n c₁ c'

/-- A program has no `coin` instruction. -/
def CoinFree (P : XProgram) : Prop := ∀ ins ∈ P, ∀ a : ℤ, ins ≠ .coin a

/-- The vendored program of a program of the extended RAM: the new instructions are replaced by
`reject`. A run of the vendored projection that gives no verdict executes no replaced position,
so it is also a run of the extended program (`XSteps.of_steps_proj`); this is how the vendored
run calculus and the compiler's segment lemmas are reused on code that mixes old and new
instructions. -/
def XProgram.proj (P : XProgram) : List Instr :=
  P.map fun
    | .base i => i
    | _ => .reject

/-! ## Cells touched along a run (PROG-3 at the RAM level) -/

/-- The cells that a vendored instruction reads or writes in the memory `m`: its named cells,
and for `load`/`store` also the cell whose address it reads from memory. -/
def baseTouches {W : ℕ} (ins : Instr) (m : ℤ → BitVec W) : Finset ℤ :=
  match ins with
  | .one i => {i}
  | .add i j k => {i, j, k}
  | .sub i j k => {i, j, k}
  | .mul i j k => {i, j, k}
  | .load i j => {i, j, (m j).toInt}
  | .store i j => {i, j, (m i).toInt}
  | .bltz i _ => {i}
  | .accept => ∅
  | .reject => ∅

/-- The cells that an instruction of the extended RAM reads or writes in the memory `m`. -/
def XInstr.touches {W : ℕ} : XInstr → (ℤ → BitVec W) → Finset ℤ
  | .base ins, m => baseTouches ins m
  | .rdIn i j, _ => {i, j}
  | .emit i, _ => {i}
  | .coin i, _ => {i}
  | .half i j, _ => {i, j}

/-- `XStepsIn P x ρ K n c c'`: an `XSteps` run in which every step reads and writes only cells
of `K`. Every run is an `XStepsIn` run for the set of the cells it touches; `K` is the
footprint. -/
def XStepsIn {W : ℕ} (P : XProgram) (x ρ : List Bool) (K : Set ℤ) :
    ℕ → XCfg W → XCfg W → Prop
  | 0, c, c' => c = c'
  | n + 1, c, c' => ∃ c₁, xstep P x ρ c = .inl c₁ ∧
      ↑((P.getD c.pc (.base .reject)).touches c.mem) ⊆ K ∧ XStepsIn P x ρ K n c₁ c'

/-- `StepsIn P K n c c'`: a `WordRAM.Steps` run of a vendored program in which every step reads
and writes only cells of `K`. The PROG-3 strengthening of `WordRAM.Steps`, added beside it (the
vendored definition is not changed). -/
def StepsIn {W : ℕ} (P : List Instr) (K : Set ℤ) : ℕ → WordRAM.Cfg W → WordRAM.Cfg W → Prop
  | 0, c, c' => c = c'
  | n + 1, c, c' => ∃ c₁, WordRAM.step P c = .inl c₁ ∧
      ↑(baseTouches (P.getD c.pc .reject) c.mem) ⊆ K ∧ StepsIn P K n c₁ c'

/-! ## Starting, halting -/

/-- The memory in which stage 2 starts a RAM program on an input of length `n`: the cell `-1`
(the compiler's argument cell `Light.Compiler.cARG1`) holds `n`, every other cell `0`. So a
compiled program receives `|x|` as its first argument (design §15c: `inLen` from an argument
cell). -/
def startMem (W n : ℕ) : ℤ → BitVec W :=
  Function.update (fun _ => 0) Light.Compiler.cARG1 (WordRAM.wd W n)

/-- The start configuration on an input of length `n`: position `0`, `startMem`, nothing
emitted, no coin consumed. -/
def XCfg.init (W n : ℕ) : XCfg W := { pc := 0, mem := startMem W n, out := [], rd := 0 }

/-- `HaltsWithin P x ρ W t v o f`: run on the input `x` with the coin stream `ρ` and word size
`W`, the program `P` gives the verdict `v` within `t` steps (the verdict step counted, as in
`WordRAM.exec`), has then emitted `o`, and has touched at most `f` distinct cells. -/
def HaltsWithin (P : XProgram) (x ρ : List Bool) (W t : ℕ) (v : Bool) (o : List Bool) (f : ℕ) :
    Prop :=
  ∃ (n : ℕ) (c : XCfg W) (K : Finset ℤ), n < t ∧ K.card ≤ f ∧
    XStepsIn P x ρ (↑K) n (XCfg.init W x.length) c ∧ xstep P x ρ c = .inr v ∧ c.out = o

/-! ## The word size -/

/-- **The word size is computable.** Some machine outputs the binary representation of
`W (|x|)` (`Nat.bits`, as in `Complexity.SpaceConstructible`) from `x` within `TW |x|` steps,
visiting at most `SW |x|` work cells. The stage-2 machine runs it once, at the start, with its
output redirected to a work tape (the R1 embedding), and pays `TW` and `SW` once. (Design §16b
item 1: `W = c·log n` for P and L, `W = c·S(n)` for Savitch.) -/
def WordSizeComputable (W TW SW : ℕ → ℕ) : Prop :=
  ∃ M : Turing.FinTM Bool, ∀ x : List Bool, ∃ t ≤ TW x.length,
    M.ComputesInTime x (W x.length).bits t ∧ M.tm.spaceUsed (M.tm.initCfg x) t ≤ SW x.length

/-- A word size computable within `TW` and `SW` is computable within any larger bounds. -/
theorem WordSizeComputable.mono {W TW SW TW' SW' : ℕ → ℕ} (h : WordSizeComputable W TW SW)
    (hT : ∀ n, TW n ≤ TW' n) (hS : ∀ n, SW n ≤ SW' n) : WordSizeComputable W TW' SW' := by
  sorry

/-- **Logarithmic word sizes** (P and L): for every `c`, the word size `c·(⌊log₂ n⌋ + 1)` is
computable in linear time and logarithmic space.

**Proof sketch.** R8.5c (`Turing.exists_inputLengthTM`) writes `Nat.bits |x|` on a work tape
within `C·(|x| + 1)` steps and `C·(|bits |x|| + 1)` cells. Its length is `logSpace |x|` for
`|x| ≠ 0` (the private `b3a_bits_length`, `Constructible.lean:66`, to be promoted) and is
fixed up at `|x| = 0`; a counter
pass over the word writes that length in binary, and a carry pass multiplies it by `c`. -/
theorem wordSizeComputable_logSpace (c : ℕ) :
    ∃ a : ℕ, WordSizeComputable (fun n => c * Complexity.logSpace n) (fun n => a * (n + 1))
      (fun n => a * Complexity.logSpace n) := by
  sorry

/-- **Space-constructible word sizes** (Savitch): if `S` is space-constructible, then for
every `c` the word size `c·S(n)` is computable in space `O(S(n))`, within some time bound (not
controlled, and not needed by the space grades).

**Proof sketch.** Run the constructibility witness and multiply its binary output by `c` (a
carry pass). It halts on every input, so the largest halting time over the finitely many inputs
of each length is a time bound `TW`. -/
theorem wordSizeComputable_of_spaceConstructible {S : ℕ → ℕ} (hS : Complexity.SpaceConstructible S)
    (c : ℕ) :
    ∃ (a : ℕ) (TW : ℕ → ℕ), WordSizeComputable (fun n => c * S n) TW (fun n => a * S n) := by
  sorry

/-! ## Stage 2 -/

/-- The time bound of stage 2: computing the word size, then `t + 1` simulated steps, each at
most one scan of a table of `f` entries of `W + O(1)` bits, one shift-and-add multiplication,
and one input seek. -/
def simTime (A : ℕ) (TW : ℕ → ℕ) (n W t f : ℕ) : ℕ :=
  TW n + A * (t + 1) * (f * (W + 1) + W ^ 2 + n + 1)

/-- The space bound of stage 2: computing the word size, then the memory table (`f` entries),
`O(1)` words of scratch, and the input length. -/
def simSpace (A : ℕ) (SW : ℕ → ℕ) (n W f : ℕ) : ℕ :=
  SW n + A * (f * (W + 1) + W + Complexity.logSpace n + 1)

/-- What the stage-2 machine leaves on its output tape: in verdict mode (`fn = false`) the
one-bit verdict, as `Turing.FinTM.DecidesInTime` reads it; in function mode (`fn = true`) the
emitted word, as `Turing.FinTM.ComputesInSpace` reads it. -/
def outputOf (fn v : Bool) (o : List Bool) : List Bool := if fn then o else [v]

/-- **Stage 2, deterministic form** (design §15a, §16b; backlog PROG-4). For every program `P`
of the extended word RAM, every output mode and every computable word size `W`, there are a
machine `M` and a constant `A` such that: whenever `P`, run on `x` with word size `W(|x|)` (and
the empty coin stream: coins read `0`), gives the verdict `v` within `t` steps, having emitted
`o` and touched at most `f` cells, `M` halts on `x` within
`TW n + A·(t + 1)·(f·(W + 1) + W² + n + 1)` steps with `outputOf fn v o` on its output tape,
having visited at most `SW n + A·(f·(W + 1) + W + log n + 1)` work cells (`n = |x|`).
[AB09, Exercise 1.9: a machine with random access memory is simulated with polynomial overhead]

Deviations: [AB09] has a bit-array RAM and the bound `T(n)²`; this is [AFM26]'s word RAM with
input, output and coins, and an explicit bound in steps, cells and word size. From the §15a draft:
no separate address width, an `n` (not `n·log n`) seek term, and the word size's own cost added
(module docstring).

**Proof sketch.** The machine is a phase host over the positions of `P` (finitely many, since
`P` is fixed), after a start-up.
1. *Start-up.* Run the word-size witness with its output on a work tape (R1 embedding), turn it
   into a unary ruler of `W` cells; count `|x|` (R8.5c) and install the table entry
   `-1 ↦ |x| mod 2^W`. Cost `TW n + O(n + W²)`, space `SW n + O(W + log n)`.
2. *One phase per position.* Each instruction kind is a `Turing.Contract` (MIG-0a) whose
   precondition says that the tapes encode a RAM configuration (a memory table of
   (address, word) pairs, a program-counter phase, the ruler, the input length) and whose
   endpoint encodes its `xstep`: find-by-key in the table (the new row of §15a), two-tape
   addition/subtraction modulo `2^W`, shift-and-add multiplication, the sign test (`bltz`), the
   arithmetic shift (`half`), table overwrite or append, the input seek R8.5b (`rdIn`, after a
   range test against `|x|`), an output append (`emit`, function mode only). `coin` writes `0`.
   Each costs at most `A·(f·(W + 1) + W² + n + 1)` steps on a table of at most `f + 1` entries.
3. *Simulation.* Induction on the `XStepsIn` run: the encoding invariant holds after every
   step, and the table holds only cells of the footprint `K` (and `-1`), so it never exceeds
   `|K| + 1 ≤ f + 1` entries of `W + O_P(1)` bits.
4. *Verdict.* At `accept`/`reject`, write `[v]` in verdict mode, and halt. -/
theorem exists_simulation (P : XProgram) (fn : Bool) {W TW SW : ℕ → ℕ}
    (hW : WordSizeComputable W TW SW) :
    ∃ (M : Turing.FinTM Bool) (A : ℕ), ∀ (x : List Bool) (t f : ℕ) (v : Bool) (o : List Bool),
      HaltsWithin P x [] (W x.length) t v o f →
        M.ComputesInTime x (outputOf fn v o) (simTime A TW x.length (W x.length) t f) ∧
        M.tm.spaceUsed (M.tm.initCfg x) (simTime A TW x.length (W x.length) t f) ≤
          simSpace A SW x.length (W x.length) f := by
  sorry

/-- **Stage 2, nondeterministic form** (design §15c, §16b item 4; backlog PROG-4). For every
program `P` of the extended word RAM and every computable word size `W` there are a
nondeterministic machine `N` and a constant `A` such that: if, on the input `x`, **every** coin
stream lets `P` give a verdict within `t` steps touching at most `f` cells (bounds uniform over
the streams, as `NTIME` and `NSPACE` require), then every branch of `N` of length
`T = simTime …` has halted, every such branch has visited at most `simSpace …` work cells, and
`N` accepts `x` within `T` exactly when some coin stream makes `P` accept.
[AB09, Exercise 1.9 with §2.1.2 (NDTMs) and Def 4.1 (nondeterministic space)]

**Proof sketch.** As `exists_simulation`, in verdict mode, with one change: the phase for
`coin i` is a single choice step whose two transitions write `0` or `1` into the table entry of
`i`; every other step ignores its choice bit (its two transitions coincide). A branch, a choice
word `w` of length `T`, then simulates the RAM run whose coin stream is the subsequence of `w`
at the coin steps; conversely every coin stream is realized by a branch that places its bits
there. All branches are runs of `P` on some stream, so the uniform bounds bound every branch. -/
theorem exists_ndSimulation (P : XProgram) {W TW SW : ℕ → ℕ} (hW : WordSizeComputable W TW SW) :
    ∃ (N : Turing.FinNDTM Bool) (A : ℕ), ∀ (x : List Bool) (t f : ℕ),
      (∀ ρ : List Bool, ∃ (v : Bool) (o : List Bool), HaltsWithin P x ρ (W x.length) t v o f) →
        N.tm.HaltsWithin x (simTime A TW x.length (W x.length) t f) ∧
        (∀ w : List Bool, w.length = simTime A TW x.length (W x.length) t f →
          N.tm.spaceUsedWith w (N.tm.initCfg x) ≤ simSpace A SW x.length (W x.length) f) ∧
        (N.AcceptsWithin x (simTime A TW x.length (W x.length) t f) ↔
          ∃ (ρ o : List Bool), HaltsWithin P x ρ (W x.length) t true o f) := by
  sorry

/-! ## PROG-3 at the compiler level: the footprint of compiled code

The vendored simulation (`Light.Compiler.sim`, `Simulation.lean:284`) produces
`Finished.run : Steps S.code n ⟨pos, m⟩ ⟨pos + s.size S.F, m'⟩` and the frame
`Finished.agree : AgreeOutside (Writable S.toSizes q) m m'`, which speaks of the last memory
only. The strengthening adds the footprint of the run itself. -/

section Compiled

open Light Light.Compiler

variable {W : ℕ}

/-- The cells that the code of a statement running in the frame `q` may read or write: those it
may write (`Light.Compiler.Writable`: scratch, `FP`, the stack from `q` on, the light memory
within the limits) and the constants it reads (`1`, `0`, `-1` and the pool). -/
def Touchable (Z : Sizes W) (q : ℕ) : Set ℤ := Writable Z q ∪ Constants Z.disp

/-- `Light.Compiler.Finished` with the footprint of the run: the same run, within the cells
that a statement in the frame `q` may touch. -/
structure FinishedIn (S : Setting W) (s : Stmt) (σ' : State) (c pos q : ℕ) (m m' : ℤ → BitVec W)
    (n : ℕ) : Prop extends Finished S s σ' c pos q m m' n where
  /-- The run touches only cells that the statement may touch. -/
  runIn : StepsIn S.code (Touchable S.toSizes q) n ⟨pos, m⟩ ⟨pos + s.size S.F, m'⟩

/-- **The simulation theorem with footprints** (PROG-3). The code of a statement matches every
run of the statement, and the matching run of the machine touches only cells that a statement
in its frame may touch. Strengthens `Light.Compiler.sim`.

**Proof sketch.** The induction of `sim`, case by case (`sim_skip`, …, `sim_call`), carrying
`StepsIn` through `StepsIn.trans`. The segment lemmas need footprint twins: straight-line code
(`stepsIn_straight`), the jump, the dispatcher, the test code, the argument and frame code, and
the loads and stores, whose addresses are known numbers: a local variable's cell
`cStack (q + x)` with `x < F` (in `Stack q Q`), a light address within `lim.space` (`Safe`),
or the return position `cStack (q + F)`. A call's body runs in the frame `q + F + 1`, whose
touchable cells lie in those of `q` (`writable_subset_writable`). -/
