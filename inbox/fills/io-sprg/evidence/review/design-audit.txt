Immediate issue to resolve before finalizing definitions
The proposed total bucket indexMap has codomain Fin(rc) x Fin(rc), with
rc(kappa)=kappa*w(kappa). At kappa=0, rc=0, but outLen(n(0)) may be positive.
Then indexMap takes an existing j into an empty type, even in its overfull
fallback. This is an impossible proposed type. Minimal refinements:
(A) preserve rc/cap rounding, use Option(Fin rc x Fin rc), none for overfull;
express correction polynomial by a sum over grid coordinates instead of total
projections, and prove the usual good-case map agrees. (B) use a padded max 1 rc
grid and disclose its finite-boundary difference. Rounding/proposed shapes may
be refined with disclosure, but the final M0 statements must resolve this.

Follow-up requested by lead: binding vs proposed issues
1. Empty grid at kappa=0 is a proposed helper-shape issue, not a false stated
Claim42/prop41. Exact rc/cap rounding can be preserved by indexMap returning
Option(Fin rc x Fin rc), with none on overfull grids; G2/G3 correction terms
become sums over coordinates weighted by the index equality. For rc>0 and
non-overfull buckets it is the original map. No mathematical theorem weakening
is needed, so this is a disclosed pre-M0 implementation refinement. Padding rc
with max1 instead would alter a settled formula and should be explicitly
listed as a boundary-rounding refinement (or escalated if treated as fixed).

2. Claim42 appears analytically sound as stated, for every P with locality,
without output stretch. For Cond1 use threshold Gamma+1: bad>Gamma implies
bad>=Gamma+1, and Gamma+1 > m log(n)/W handles the floor even for tiny m.
Condition on I for independent noise-instance bounds; shared sigma is harmless
because BAD depends only on noise and Vars. The common bucket-overflow event
is split off once. Polynomial B times exp(-kappa) is eventually o(2^-kappa),
and Cond3 is superexponential from cap>=kappa^2. kappa=0 is harmless for the
statement because it is eventual.

3. Target uniformity has a substantive potential E-ROUTE issue, independent of
source: Params.delta ranges over arbitrary real constants. For a
noncomputable delta in (0,1), w(k)=floor(k^(E*delta/2)) is not a computable
sequence (eventually max1 is redundant): from w one can compute delta to
arbitrary accuracy via log(w(k))/log(k), with effective error O(1/log(k)).
The proposed fixed-width seed encoding exposes w through output length.
Concrete test family: E=d=D=1, BoolPRG output length m(n)=0, unit index/draw,
constant empty output and vacuous multilinear representation. This is allowed
in Params (no HasStretch field). Then B(k)=1, Gamma(k)=0; the index and exact
seed draw inputs are independent of delta because the noise vector has
length n=k (CAUTION: n is the seed length, not output length; see below).

Correction to the quick counterexample: the seed draw noise vector has length
n, not m. Thus its Fin W coordinates' encodings can reveal some information
about W through their fixed widths. The simple input-independence claim needs
an exact draw encoding before it is a complete counterexample. If each Fin W
is encoded in W bits (permitted though exponential for arbitrary W?), inputs
would reveal W; if in ceil(log W) bits, a zero draw reveals only that width,
and w remains generally noncomputable relative to that coarse schedule, but a
countability argument or a fixed-width subsequence is needed. Therefore do
NOT label this a proved E-ROUTE counterexample yet. The concern is real:
Phase B cannot in general calculate arbitrary-real rpow floors from unary k
alone, unless the parameter word/draw encoding deliberately supplies all
needed dimensions. Final target shapes and their inputs must resolve it.
A rational exponent or rational minorant schedule is a standard remedy but
would be a disclosed change to the settled rounding convention.

Refined uniformity obstruction (supersedes tentative correction above)
Under the intended injective fixed-width encDraw and parameter word y carrying
only encoded pp/index, T5 DrawSamplable entails computability of card(Draw).
For k>=1 its failure is <=2^-k<1. Exact-on-success makes every draw reachable.
Enumerate all c.eval(k) coin strings and run the computable UniformSampler.raw;
count distinct nonfailure words. Encoding compatibility and injectivity make
this exactly card(Draw k pp). This argument needs no independent computation
of encDraw itself, so dimensions leaking into its words do not evade it.

Take E=d=D=1 and a permitted BoolPRG with m(n)=0 and unit index/draw. B=1,
Gamma=0, so the fixed zero index/matrix's encoded parameter word y is
independent of delta. Choose a computable prime schedule by unbounded prime
enumeration (only as a meta computability argument, not an honest algorithm).
Draw cardinality is 2^k * W(k)^(k^2) * p^(2*k^2). Division and integer roots
recover W and w effectively for every k>=1. For k=2^N,
0 <= delta - 2*log(w(k))/log(k) <= 2/N, since
w<=k^(delta/2)<w+1<=2*w. Thus w computes delta with an effective convergence
rate. Pick any noncomputable real delta in (0,1): no such T5 witness exists.

Consequences/classification:
- Not a false conditional security theorem. P.Targets is allowed as a
hypothesis, so raw/conditional statements can be logically sound.
- The proposed existence hypothesis forall P:Params,P.Targets cannot hold
for the full arbitrary-real Params type with those intended inputs/encodings.
This is exactly a concern about an efficiency target with no possible
algorithm for allowed data, covered by the dispatch E-ROUTE criterion.
- It is not source fidelity evidence; PDF still pending.
- Minimal viable fix: make exponent data rational (coerced to reals for
analysis), or use a rational minorant in the rounded schedule, with theorems
quantifying arbitrary analytical delta through that minorant. This changes a
settled rounding/parameter convention and should be disclosed to user as
E-ROUTE if implementing it.
- Alternative of putting w/W in y means external noncomputable scheduling,
which changes the intended honest algorithm input contract and should not be
silently used to make the targets look satisfiable.
- Actual M0 encodings/parameter words have not been authored; until fixed, state
this as a precise obstruction to the intended proposed shape, not a theorem
about already-existing Lean declarations.
