# Pinned Lean 4.25.0 local irreducibility batching review

Source-only review. No Lean/Lake process or active source/evidence mutation was performed. All file references below are relative to `/Users/seyoonr/.elan/toolchains/leanprover--lean4---v4.25.0/src/lean/Lean/`.

## Conclusions

One `attribute [local irreducible] $[$ids:ident]*` command is grammar-supported and preserves the ordinary handler route, provided the list is nonempty, contains exactly the intended already-resolved constants, and excludes currently irreducible entries. It reduces command-elaboration and attribute-elaboration overhead. It does **not** remove the per-name `liftTermElabM` or per-name saved environment contexts that the attribute builtin constructs. A large memory improvement from batching alone should not be asserted without measurement.

A single `Command.liftCoreM` block invoking the registered irreducible handler with explicit `.local`, under `withExporting (isExporting := false)`, is the direct public API route that removes that per-name Term/Info machinery while preserving the builtin handler's private validation and scoped environment update. ``Attribute.add n `irreducible Syntax.missing .local`` is also public and validated, but looks up the same handler again per name. Fetching `getAttributeImpl` once and calling its public `.add` field avoids those repeated lookups. `Syntax.missing` is explicitly accepted as a no-argument builtin attribute syntax.

Do not replace the attribute handler with `setReducibilityStatus` or `setIrreducibleAttribute`: those public setters perform an unvalidated **global** update, not the validated local attribute operation.

## Exact source evidence

* `Elab/Declaration.lean:299–314`: command grammar ends in `many1 ident`; `elabAttrs` runs once at312, but each identifier enters `withRef ident <| liftTermElabM` at314. Names are resolved with `realizeGlobalConstWithInfos` and ambiguity checked at320–329; `Term.applyAttributes` is called at330. Global-import dependency tracking at333–337 is conditional on `.global`, so it is absent for the proposed local operation.
* `Elab/Command.lean:446–466`: `elabCommand` adds logging, reference, recursion-depth, macro-scope, trace and dispatch wrappers per command. Batching removes repeated instances of these wrappers.
* `Elab/Command.lean:689–703`: each `liftTermElabM` adds `withSaveInfoContext` at696, initializes/runs Term and Meta state at700–702, and commits that result via `runCore`. `runCore` at163–210 also reconstructs the Core context/state, reads the initial heartbeat count, and appends the newly collected info trees to command state.
* `Elab/InfoTree/Main.lean:20–32`: `CommandContextInfo.save` includes the current `env` and options, name generator and namespace. Lines419–435 attach a saved context to the newly collected info trees whenever info collection is enabled; `withSaveInfoContext` at442–453 uses that function. `Elab/InfoTree/Types.lean:25–32` confirms the saved context stores an `Environment`. Thus a batched attribute command still retains per-name environment versions through its per-name Term elaborations. These are persistent environment references, not evidence of full deep copies.
* `Elab/Term/TermElabM.lean:927–963`: ordinary attribute application enters `withDeclName`, then `withExporting (isExporting := attr.kind != .local && !isPrivateName declName)` at939, per-attribute tracing/logging and info nodes, and invokes `attrImpl.add declName attr.stx attr.kind` at946. `applyAttributes` passes application-time `none` at969–970, so the direct immediate handler call does not skip an application-time restriction applied by this command route.
* `Attributes.lean:20,54–63,487–503`: `AttrM` is `CoreM`; `AttributeImpl.add` and `getAttributeImpl` are public; public `Attribute.add` simply fetches the handler and invokes `.add`. Its default kind is `.global`, so `.local` must be explicit.
* `Attributes.lean:87–94`: `ensureNoArgs` accepts `Syntax.missing` explicitly. Do not pass an entire `attribute` command as the handler syntax.
* `ReducibilityAttrs.lean:102–133`: `validate`, when `allowUnsafeReducibility` is false, requires a definition, rejects `.scoped`, rejects local reducible, and permits local irreducible only from semireducible at127–129. Already-irreducible skipping remains necessary. Lines135–139 show the registered handler performs `ensureNoArgs`, `validate`, `getCurrNamespace`, then the update. Lines141–148 register exactly this closure as `irreducible`'s handler.
* `ReducibilityAttrs.lean:61–72`: `.local` uses `reducibilityExtraExt.addCore`, whereas `.global` follows the persistent/global branches. `ScopedEnvExtension.lean:173–181` routes `.local` to `addLocalEntry`; scope rollback is the ordinary stack mechanism at133–142. The direct registered-handler route therefore preserves local lifetime without inserting another scope.
* `ReducibilityAttrs.lean:168–174`: the public reader is safe; the public setter calls the private core setter with `.global` and performs no validation. `setIrreducibleAttribute` at192–194 delegates to that global setter.

## Bounded implementation cautions

1. Keep the same actual `Name`s from the catalog/request. The command route resolves syntax and records IDE references; direct handler invocation uses exact names and intentionally omits those resolution/IDE effects. The eligible request names are already constants in the inventoried environment, so no deferred name realization should be needed; reject any missing name rather than inventing a fallback.
2. Preserve the idempotency check immediately before each application. If prefiltering once for a batch, also reject/deduplicate repeated names: two semireducible occurrences of one name would both survive prefiltering, then the second local attribute application would be rejected after the first changes its status.
3. Explicitly keep `allowUnsafeReducibility = false`; do not enable its override. An unexpected reducible or non-definition entry should fail under the same validation instead of being coerced into eligibility.
4. For direct handlers, wrap the entire single Core loop with `withExporting (isExporting := false)` to match the ordinary local-attribute path. That wrapper restores the previous exporting flag even on failure (`Environment.lean:2691–2698`). The irreducible handler itself uses none of the omitted Term declaration-name, metavariable, or info contexts.
5. Error behavior differs: ordinary `Term.applyAttributes` uses `withLogging`, which logs a handler exception and continues (`Elab/Util.lean:240–245`); direct `.add` throws and can stop the loop. Successful installs have the same reducibility/scoping effect. Keep fail-closed handling and the final exact expected-count/status assertions; do not report a partially completed loop as sealed.
6. A single Core loop shares a Core heartbeat context instead of resetting it per name (`Elab/Command.lean:163–185`). Preserve the harness's declared heartbeat policy; do not describe this operational change as identical command scheduling. No performance measurement was made by this source-only audit.
7. The handler still performs per-name validation and persistent scoped-map updates. Removing saved Term contexts does not remove this required work or establish a numeric runtime/memory bound.

The direct public-handler proposal requires a fresh native probe/control validation before replacing any live evidence generator. This review makes no claim about an unexecuted candidate.
