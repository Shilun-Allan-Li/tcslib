# Pure immutable module-name cache

This candidate is based on the original stable native-hardening-r1 generator, not the Core-loop candidate. Only `seal_command` changes. Both catalog and per-request home checks now read `moduleNames[mi]!`, where `moduleNames := env.header.moduleNames` is bound once immediately after the existing captured `env`. The two original expressions used this same immutable `env`, never the changing current environment, so every indexed value is definitionally the same. Attribute application cannot mutate the already-captured `env` value. There is no change to enumeration, filtering, actual Name arrays, ambiguity detection, definition/status validation, attribute semantics, requests, logs, EOF verification or controls. Reversing these three textual edits restores the generated original output byte-for-byte in all six source-only cases (empty/3/1438 requests, INSTALL/EOF).

Pinned Lean source `Lean/Environment.lean:195` defines `EnvironmentHeader.moduleNames` by mapping the module array. The old per-constant expression can therefore repeatedly build that array. Binding it once is pure memoization. A native benchmark remains necessary to quantify the gain. No Lean has been executed for this proposal.
